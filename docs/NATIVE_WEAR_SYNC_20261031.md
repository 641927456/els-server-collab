# Native104/105 pending-response guard

Successive right-click unequips can select the same empty bag position before
the preceding105 reply updates the native inventory. The first succeeds; the
next then describes an incompatible swap and the server returns a generic
error. The observed ordinary equipment and accessory cases share this path.

The original22634A0 helper sends104 and registers a105 wait through74FB70.
Its native74FA90 wait query is not used at that entry. This candidate adds one
guard there, calls the original helper with all seven arguments unchanged when
no105 is pending, and returns false while the preceding move is outstanding.
It uses the original completion/timeout/exit lifecycle and adds no queue,
timer, retry, packet edit, inventory mutation or server destination guessing.
Explicit swaps retain their original behavior after the preceding response.

The three runtime leaves are listed with exact hashes in
`references/native-wear-sync-20261031-v1/candidate.json`: one existing startup
composer and two new support files. The existing cache, relationship and login
composition is recovered exactly after removing the added installation. The
original game EXE/KOM, server rules, saves and current pointers are untouched.

Verification covers original x64 query/add/remove in private Unicorn memory,
12 cases in a real Frida17.23.3 owned native ABI process, source-build identity
rejections, and the startup composition inverse. The ABI fixture preserves the
original request prologue and query body, but does not execute the whole game
request body. No player process was attached. These are author checks, not an
independent Hook review or natural GUI acceptance.

Run `python -B tools/verify_native_wear_sync_candidate.py` for the portable
archive check. Full native/ABI tests require the existing private image and
tools; their sanitized results are in `verification.json` without raw captures,
runtime logs, databases, clients or credentials.

This candidate is unselected and uninstalled. Before delivery, the designated
publisher must obtain the required independent Hook review, verify the actual
isolated game105 lifecycle and startup load, then include all three files in
the signed raw LOCAL, signed LOCAL and signed Friends source/component sets.
It does not authorize a merge bypass or a second publisher. Original scripts
and current-engine remain selected until that delivery. Script removal or the
guard's explicit dispose restores the original function; no save rollback is
needed. Issue #638 remains open until actual delivery acceptance.
