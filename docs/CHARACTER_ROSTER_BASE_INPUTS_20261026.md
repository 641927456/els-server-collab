# 列表和创建回包的当前基础输入（Issue541）

进入角色、副本成员、转职、领奖和退出副本使用正确的基础输入，但列表与创建回包使用同一DTO的另一个模式，仍发送两组全零测试向量。于是同一99级角色在列表/创建消费者和进入角色消费者中读到不同的来源。

仅在完整DTO带有明确角色身份时，填入已批准的公开成长输入。两个原有七浮点字段宽度、位置和顺序保持；原有经验初始化条件、装备图、称号、技能、经济字段和没有角色身份的旧私有夹具保持。无需新客户端Hook、新表、存档迁移或补发物品。该公开成长规则的来源及限制仍见 CHARACTER_BASE_INPUTS_20261026.md，不冒称恢复官方裸装公式。

双端每端195职业×1/50/99级×两种模式，均由锁定客户端原始D9B170完整读取。已初始化模式及无角色的旧夹具字节保持；列表模式仅两个已有基础记录变化。用户提供的只读22件穿戴快照亦能完整解析，未修改玩家数据。双端真实App/TLS首次和冷角色列表、进入角色原生读者、库存/余额保持及自有认证清理通过。

实际正式父版另有已经交付的三行疲劳DTO读者，公开主干尚无其依赖模块；本PR只转移同一条件变更，不引入悬空导入。正式候选保留那三行，两份源码除该既有增量外一致，来源差异及两份SHA在私有发布绑定中明确区分。

该修复不填充独立战力缓存，不宣称全部条件效果或自然战斗正确。生产发布与Git合并独立，按队列从届时实际正式父版最小合并并保留较新改动。
