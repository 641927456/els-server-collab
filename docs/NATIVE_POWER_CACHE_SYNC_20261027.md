# 当前原生战力缓存同步候选

Issue #560。已核固定客户端的主面板通过原生896870计算完整战力，但独立的Unit+3048缓存加载后仍为0；部分原力消费者读取这个缓存。用户明确批准“允许最小原生同步，验证合格后安装”。候选只调用原生完整计算与8A1400写入，不增加伤害公式，不把装备或称号重复加进裸装输入。

`references/native-power-cache-sync-20261027-v1/`保存当前正式共同入口的五叶候选。沿原有Field/Dungeon回调同步当前拥有角色；露／希尔分别计算两侧后沿原加载流程取较大战力。保留主线程、所有者、职业、原生代码与资源身份约束，避免计算器重入，并在已核缓存读取处检查同步。原EXE、KOM与原trace文件保持。启动前生成载荷；同步被拒绝时结束本次自有启动，记录具体错误。

仓库启动基线与当前正式启动器的私有资源合同不同，因此这里先保存明确绑定的候选，不覆盖较旧启动基线。候选注册表加入两个新依赖及共同驱动的SHA；缺失、篡改或未知客户端都拒绝。正式安装必须从届时实际双端与启动器父版继续，并完成完整入口检查及签名分发。

已核单机正式入口与签名启动器V38的原trace有两处既有差异，涉及线上暂缓的艾因／莉缇娅适配。本次分别保留两个父trace，不整份互盖；`approved-hosts.json`只列这两个明确审查的父文本摘要。两个入口共同使用本次V8核心，签名启动器沿不含暂缓适配的原父继续。`launcher-host/`只保存其校验器与注册表差异，五叶源映射见`candidate.json`。

之前V3已核独立原生完整报文，Eve武器与称号穿卸，真实原力书及原生穿卸请求，共鸣实际100点攻击分配与原生应用回包；原生原力临时算值中，战力12583时两个系数由0.10增为0.11。V3前7家族91职业及7个冷Actor通过，第8家族多轮在原生计算器内发生system异常，同步禁用；这些失败保留。

本次V7只把NativeFunction异常行为由steal改为propagate，让客户端处理自己的原生异常；不重试计算、不替换结果或异常编码。无附加异常观察钩子的第8家族13职业及新进程冷Actor通过，另两轮同家族只读诊断完整通过。附加抛出点／生产者返回观察的另一轮发生原生退出，仍为失败；嵌套观察存在盲区，后续不改异常记录／上下文的只读原生观察，已确认旧行为的实际异常编码为0xE24C4A02，与LuaJIT原生Windows异常编码一致；不再仅据静态路径推定类型。上述均为受控验证。

V7的新一轮通过9家族117个受控职业及9个新进程冷Actor，第10家族在角色加载前启动超时，独立诊断同样保留失败；不含缓存候选的原入口对照成功进入角色。V8保留V7原生计算核心，仅将六处缓存挂钩和原生调用包装器初始化延后到既有Field／Dungeon回调；启动阶段35秒检查准备状态，首次拥有角色的Field回调后5秒内必须就绪，失败仍结束本次自有启动。露／希尔13职业、原生双侧战力及新进程冷Actor已通过，V8全家族验证进行中。当前V8仍禁止安装。全195职业／15家族、生命周期与组合战斗、签名入口及双端正式安装验收尚未完成；不沿用旧核心91职业冒称新核心全部通过，不以Git CI代替原生实测。

另外，受控原生对照确认副本Actor的HP／攻防基础输入仍可能是裸装七项，而完整原生聚合已包含当前装备和称号。单个最终HP字段的私有报文对照已定位到独立输入缺口；完整七项及其百分比／效果阶段仍需核定，扩展客户端属性消费者的范围正在单独确认。本缓存候选未覆盖这一修复，不据缓存非零或已发生命中宣称最终伤害和全属性已经全部正确。

无SQL结构或玩家数据迁移。恢复采用原共同入口、旧组件合同与旧签名分发版本，保留所有后来交付的服务器业务和玩家库；不恢复账号或角色数据库。
