# 单人复活复用客户端原生选点（Issue #241）

先前将组队需要的明确出生点白名单同时用于单人，使 `30000` 后续两段和 `30072` 三段的本人复活也被拒绝。当前同版客户端的 162 消费链支持 `position=-1`：本人分支从已经加载的当前场景出生点表选点，再由客户端完成位置、方向和复活处理。单人没有观察者需要统一落点，服务端无需解密世界脚本、复制 LineMap 加载或重做随机选点。

本次只补服务端准入的职责分离。严格单人普通副本 `30000`、`30072` 各允许 `stage 0..2/part 0`，新增单人准入条目共五项：`30000` 的 stage 1、2，以及 `30072` 的 stage 0、1、2；`30000/stage 0` 原范围保持。准入仍绑定同版地图定义与路线来源 SHA、当前角色和租约、单人参与者、实际加载阶段及合法死亡来源；每条生命只原子扣本人已有合法来源余额 C 一次，保存回执。进入队伍或共享房间不会静默降级成单人。

组队仍只允许 `30000/stage 0`，原 12 个来源已核出生点键保持；同房 AC/162 与同落点机制不变。只有明确键才能让复活者和观察者使用同一落点，不能向组队成员各发 `-1` 随机选择。其他共享地图与阶段的明确落点来源继续待核。既有组队实现、验证分层与未验边界见[组队说明](SHARED_OWNED_REVIVAL_20261021.md)。

## 改动与当前来源

本候选六个运行叶中，相对已合并的组队源码仅修改四个：流程、地图读取模块、地图 JSON 和 manifest。协议与存储两叶逐字节保持，不新增表结构、客户端文件或启动器载荷。数据锁定当前客户端 `6c6b51809aec90f9b717a9e55d679f221315a6296d69da80510e3456423a1709`；未复制其他地图坐标或猜测 World/LineMap 文件关系。单人原生选点依据当前已归档消费者链，2014 端仅参考本人消费、死亡资格、回执与多人通知的职责，不移植旧数值规则。

已独立审查本次六叶源码和单人 `-1` 消费职责。八资源离线分析的首项 `UcError()` 及其余七项未执行记录保留；它们不再作为严格单人选点的阻塞理由，后续另获明确许可的单资源诊断已执行一次，仍未恢复明文；除此不自动重试或扩大范围，也未从失败中声称恢复了其他组队落点。

## 实际验证与待交付

两条新增的实际鉴权私有单会话回环 TLS 流程分别走完 `30000` 和 `30072` 的三个阶段，每段本人复活一次：C 从 10 依次变为 9、8、7，生命回执在同次运行中依次为 1、2、3，162 保持 `-1`。经过服务端正常 AD/BB/C1 路径推进，验证活着时重复请求及跨阶段旧死亡上下文不会再扣费；冷重新鉴权选角的完整 2A 与当前读取器一致，余额为 7，未记录 transport 错误。五个新增准入条目由这两图各三段的流程覆盖，不把五个条目算作五条独立 TLS 会话。

另有实际鉴权双会话 `30072` 负例：加载前和正常组队加载后均拒绝本人复活入口；双方 TCP fence 后没有 AC/162，双方余额仍为 10、账本没有新增生命消费。现有 `30000/stage 0` 组队成功证据复用，没有重跑输入未变的旧成功方法。

这些验证使用自有临时库、明确的等级与 190556 来源箱预置，没有注入游戏 HP、死亡阶段或怪物状态，没有运行或修改客户端、SDK及正式服务。它们证明服务端协议、准入、事务、跨段生命编号和冷读，不等于客户端实际选点、自然界面或真实战斗通过。实际组队 TLS 覆盖仍仅 2 人，3/4 人组合仅过资格源码审查，尚未实测。

本候选**尚未安装本地或线上**：最近的交付保护检查发现游戏仍在运行，正式两端发布头保持，Git 源码交付不等于部署。自然 GUI、真实玩家多人实战及其他共享地图仍待，SDK 继续放在本轮范围外。不新增每日免费次数、免费余额、现金补付、共享复活石池或队友代付规则；客户端已有 HP/MP、效果、计时和界面继续复用。
