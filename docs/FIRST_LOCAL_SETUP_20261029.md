# 从 Git 使用统一启动器玩本地版本

1. 完整拉取仓库并保留 `.git`。需要 Windows x64、Git，以及匹配的游戏客户端。
2. 双击仓库根目录 `启动统一启动器.cmd`。首次联网下载并校验统一启动器和本地运行环境。
3. 统一启动器自动完成本地初始化，进入“本地版本”。选择自己的客户端 `data/x2_dx11.exe`，点击开始单机冒险。

若已经打开统一启动器，点击“本地版本”后选择 Git 仓库根目录：里面有 `.git`、`els_server` 和 `channels`。初始化不再要求用户预先提供 `releases/local/current.json`。旧的已安装服务端工作目录仍可继续选择。

首次初始化不要求安装 Python 或 GitHub CLI，不调用旧的本地测试启动器，不下载或修改游戏 EXE/KOM。运行环境使用固定 TLS 端点、RSA 签名、大小和逐文件 SHA 校验；Git 中的 LOCAL 来源也必须与签名包的已验收来源完全对应。开发环境中的 Python/GH CLI 准备说明仍供协作开发使用。

## 存档与重试

本地安装位于仓库 `.runtime-cache/unified-local/releases/local/`；玩家自己的存档在 `.runtime-cache/unified-local/state/integrated.sqlite3`，首次启动时由现有服务端正常生成。初始化不导入任何作者账号、玩家库或测试存档种子，不覆盖已存在的存档。线上账号和本地存档分开保存。

下载中断可以重试，已校验组件会复用。安装只有完整校验通过后才生成当前版本指针；完整安装已落盘而指针创建中断时，重试会核对全文件后补齐指针。未知、不完整或被修改的安装会保留并提示失败，不自动删除或用旧备份覆盖玩家数据。

已有完整安装可直接启动；运行包缓存清理后也不会要求重新初始化。请保留 `.runtime-cache` 下的存档。若要删除仓库或迁移电脑，先退出游戏并备份自己的 `state` 目录；不要将自己的存档、账号、缓存或日志提交到 Git。

## 更新边界

新初始化的本地安装只接受与该版统一启动器签名 LOCAL 包一致的已验收来源。一键更新先正常快进 Git，再核对来源；来源不匹配时保留当前安装并提示更新统一启动器，不使用协作根目录代码直接覆盖 LOCAL。该安装绑定最初选择的仓库，不允许改选另一个源码目录后落入旧覆盖安装路径。

历史已安装工作目录继续使用既有备份、锁和更新流程。原 LOCAL 差异、GM、商城、原力、公会和既有支持组件按已交付来源保留。本次修复只核收首次初始化、独立存档与共同启动链，游戏自然界面、战斗和多人效果仍按各自证据核收。
