## 修复前最小核对

1. 明确具体对象与操作：名称／ID、角色还是账号、正常入口、玩家预期、实际失败证据。
2. 核使用条件：角色／转职／超越／大师阶段、等级、前置任务、场景、副职业、装备类别／部位、锁定／封印／有效期、背包目标栏容量、是否已拥有、购买与权益状态、次数及重置时区。只列该系统真实相关条件，不凭想象增加限制。
3. 区分查看、预览、登记、应用、结算、领取和重复领取；读取空列表或合法拒绝不能一概当功能缺失，也不能据此忽略空白UI或错误提示缺陷。
4. 写出“最新玩法目标／本地当前行为／具体差异／来源与未证部分”，再核共享入口、原生消费者和事务。资源不支持时记录兼容缺口，按既有适配边界推进。
5. 测试夹具先证明满足真实条件。基础职业或只改class的角色不能冒充完整大师阶段；模板存在、预览成功不能替代真实使用。正向流程、合理拒绝、保存及冷读分别核收。
