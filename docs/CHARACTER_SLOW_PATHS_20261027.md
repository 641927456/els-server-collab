# 建角、选角、进城与 SQLite 持锁

Issue #572。本候选从已交付架构版双端源继续，保留 #570 周期合批和有界纯口令准备。当前源索引是候选，正式发布前须按届时实际父版最小合并并重新核验，不用旧父整树覆盖。

## 根因与调整

建角 `Characters.create` 在 BEGIN IMMEDIATE 内调用 `create_ack` 做提交前编码验证。冷进程首次构造 DTO 会加载并逐行核验全部原生装备资格/实例证据；隔离剖析中出现数十万次资格条件检查。原生证据验证不能删，也不能把编码验证移到事务外。

新增 `prepare_character_catalogs` 只预载既有 SHA/边界校验的不可变定义。服务监听及角色存储构造前预载；独立 `Characters.create` 仍在 BEGIN 前显式准备。角色资格、容量、日限额、UID/库存分配、同事务建角回复编码和幂等回执保持原顺序。成本移到进程启动，不能据此称静态校验本身变得更快。

`for_character` 只需核当前归属及最终删除状态，使用已有实时 `Characters.identity`，不重复构建完整 DTO；最终 wire 消费仍走原全字段投影。库存快照只在一个业务操作内复用，逐次检查 SQLite data_version、文件身份、owner/store/对象及秒边界。每次入口仍先执行库存初始化和旧 circuit 修复，没有权限/角色跨请求 TTL，返回深拷贝。外部提交、换文件或不同操作必须重新加载。

位置保存先读已提交的实际字段；完全相同时不取得写锁、不增加 revision。有变化仍使用原 BEGIN IMMEDIATE，并在取得锁后重新读取再写入。资格、位置范围校验与最终 load 保留。

## 锁等待与事务计时

针对 Characters 两个原写事务及 LocalState 四个原显式事务，新增 `write_transaction` 观察：分别记录 BEGIN 等待、取得写锁至提交/回滚的时间、BUSY/LOCKED 及回滚计数。不记录 SQL 文本、参数或玩家身份，维持原 sqlite3.Connection 类型、10 秒超时、错误、隔离及日志有界窗口；不加入重试、PRAGMA/WAL 或更多业务写线程。

独立写者测试保留真实争用：有变化的写入仍等待并重新读取最新提交；相同位置在已保留写锁但允许读取的场景不再无故排队。SQLite EXCLUSIVE 锁或其他存储路径仍可能等待，本批没有消除全部数据库锁风险。

## 验证边界

隔离同机、各五个自有建角及十次首次/冷选角进城的对比，五个建角回复 SHA、十个角色读取 SHA 全部相等。首次建角 handler 约 914.8→57.7ms，首次选角 124.7→105.5ms、首次进城 91.5→89.4ms；暖样本变化小且受并行工作负载影响，不能当自然玩家 P95。正式新父及线上最终样本另以本批冻结回执为准。

定向覆盖提交前编码失败全回滚、同回执不重复发物、归属/最终删除、库存深拷贝、外部写/文件代次/秒边界失效、取消/清理、实际 SQLite 竞争与 BUSY，以及全部保留的架构/称号/HP/Hero/协议回归。旧全路线资格、故事与疲劳夹具缺口及自然 GUI/多人实战不降低门槛来消除。

无客户端、表或安装 DDL，没有恢复玩家库。所有现有正式增量和 LOCAL 差异需按实际父清单核收；Git/CI 通过不代替双端安装、备份、正常排空、至少 120 秒观察及精确 QA 清理。

## 单操作只读连接边界

后续边界候选额外复用归属查询和库存快照的只读连接；仅在单次业务操作及当前线程内存在，无权限值/跨请求缓存。外部提交仍可见；嵌套活动读事务使用独立临时连接；无论成功或异常退出都结束读事务，操作结束关闭全部连接。新增四项覆盖只读拒写、提交可见、嵌套隔离、错误后写者可立即提交及仅身份读后的文件代次切换。该修订在Rosso父重建双端156项，151通过、5通道跳过，未安装。最终交付需从正在收尾的Aurora实际双端父继续，旧八叶冻结保持未安装。
