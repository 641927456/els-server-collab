# 34320 ordinary-party material allocation

This is the server owner's rule authorized on 2026-10-23. It is not a claim about current Chinese retail allocation or drop rates.

For an ordinary party of two to four valid members whose original source segment is loaded, each member independently uses the existing 25% material draw. A hit selects one of 118177 or 118178 uniformly and awards one of that material plus one 118186 from the same hit. There is no extra party multiplier or new damage/death threshold. The scope is only map 34320 and its verified original Boss sources: Stage 2, part 1, templates 7519/7520; Stage 3, part 0, template 7511. Other maps, modes, solo rules, EXP and generic loot allocation retain their existing behavior.

The server retains the original room, member, account, active character, region admission, source generation and stage checks. Each owner keeps an individual issue and reward UUID. One real SQLite writer prepares all affected members' quest progress and material issue receipts, protocol encoding and bounded mailboxes before commit. Refusal or preparation failure rolls back the whole operation. Retries reuse committed receipts without drawing again; a rolled-back attempt has no committed draw receipt and may draw again on a later valid attempt. Pickup uses the existing native CF/D0 and inventory notifications. The narrow Stage 2 part 1 to part 2 claim reuses the issued source and death proof, including the distinction between the shared source UUID and an owner's reward UUID.

The four source leaves are the new `friends_material_loot` adapter, its existing friends-death route, the finite-loot claim binding and the finite-loot storage transaction support. This port also includes the previously delivered solo cross-part `_claim_context` guard because the Git parent lacks it. It preserves the Git parent's unrelated portal qualification code rather than copying a newer whole file.
