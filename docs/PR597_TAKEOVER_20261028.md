# PR597 接手修正与回归

PR597 的旧分支将首次技能书回执判断移出正确作用域、把脚本门放宽到原生团本控制器，并覆盖仍受历史清单约束的掉落来源，导致空库异常、提前放行和完整来源 CI 失败。其可采用部分已经通过 PR600/601、603/604 进入主干并完成双端交付。

本次从 main `93c31fc` 接手，正常合入原 `d34246f` 历史，逐项核对原 54 个变化路径，采用主干已经合格的实现取代旧错误集成。原提交作为父历史保留，普通 fast-forward 推回原分支，不强推、不篡改旧失败记录。相对主干只增加回归、来源证据和 CI 调用；实际运行源码、默认 profile、LOCAL 差异及 V39/V40 支持映射保持。

## 三项具体修正

- 技能书继续采用当前事务实现：首次无回执表、幂等重发、冷读、拒绝及失败回滚均按真实私有临时库验证；冻结旧函数作为负控，证明旧分支的 `UnboundLocalError` 确实可复现。保留已交付的原任务刷新和完整编码预校验。
- 门条件保留原生退场约束。34140 三阶段控制器 6851/6853/6855 尚未退场时拒绝，实际退场后准入；30282 的固定图／模板156 kind1 门和已交付30182的固定图／模板145 kind3门保持。对其他原图条件扫描并测试地图、图SHA和对象条件变化，避免再引入通用 inactive 门放宽。
- 掉落来源恢复正确历史字节。旧 PR 将3422字节／`31a5c4c5…`的受锁定来源改成4773字节／`8fa0415a…`并扩四图；现有 materializer 拒绝该变化符合合同。回归覆盖合法源通过、旧源拒绝、只伪改大小仍被 SHA 拒绝；历史清单及 SHA 保持。

回归针对当前 `current-engine` 选用源码，不把过时协作根目录当作正式运行版本。旧反例仅作不参与运行选择的冻结测试输入，CI 不依赖开发机绝对路径或 checkout 的祖先对象。
