# 宠物自动用药不再用 -1 画白框：等待与拒绝都改走聊天提示

副本与野外里宠物自动使用药水时，0x65E 的两种「还没到点」和几种「用不了」原本都回 `result=-1`。客户端的错误文案表只有 `0..0xC4D`，`-1` 落在表外解析为空串（`social_messages.chat_ack` 注释即此结论），于是玩家看到的是一个只有「确认」按钮的纯白弹窗，既不知道哪一步失败，也没法据此处理。同时客户端拿到 `-1` 会立刻重发，2026-11-05 15:41:15–18 的会话里 3 秒内出现 56 次 0x65E，全部被判 `Consumable is cooling down`。

**等待**（`Waiting`）：`consumable_cooldowns` 未到期记 `item-cooldown`，`pet_auto_cooldowns` 未到期记 `pet-interval`。`_waiting_reply` 回 `0x65F result=0`，把真实剩余秒数写进原生 `cooldown` 字段（槽位图标据此倒数），再追加一条 `0x87` 频道 0 系统行：

- `[系统] 「<道具名>」的冷却时间尚未结束，无法使用。（剩余 N 秒）`
- `[系统] 宠物自动使用间隔尚未结束，请稍后再试。（剩余 N 秒）`

**拒绝**（`REFUSAL_TEXT`）：没有激活宠物、自动槽未设置、背包里没有可用的恢复道具、角色等级不足、道具本身不可自动使用，这五类按同一口径回 `0x65F result=0` + 一条系统行（`use-refused` 记日志），不再画空框。

同一 `(槽位, 原因)` 4 秒内只发一条，避免连发刷屏。协议与授权类故障（请求形状解析失败、非当前租约、非游戏角色）仍保留 `-1`：这些玩家无法处理，空框反而应作为缺陷信号暴露，`state/pet-auto.log` 里分别记 `use-rejected`。

定向回归 `tests.test_pet_auto_flow`：等待回 `[0x65F, 0x87]`、`result=0`、`cooldown>0`、两类等待文案、拒绝文案（清空背包后）、等待与拒绝都不扣道具、节流窗口内只剩 `0x65F`；`tests.test_pet_support` 与 `python -m els_server --check` 通过。线上热加载于 15:57:20 / 16:03:24 两次装载，随后 0x65E 正常消费（template 77000）。客户端把频道 0 系统行渲染成何种样式（是否带本角色名）仍需实机截图确认。
