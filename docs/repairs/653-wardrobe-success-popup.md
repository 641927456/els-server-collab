# 衣架批量变更成功弹窗

批量变更一件或多件外观时，4B2 的登记 map 被客户端同时用于合并登记状态和生成“以下道具将登录为衣架道具”列表。服务端此前发送全账号登记表，因此已有外观越多，成功弹窗越长。

4B1 只应用已登记外观，不创建登记来源。本次将首次成功及回执重放的登记 map 设为空，继续发送实际变更的物品向量。4AF 登记回包、完整 31 初始化、资格校验、事务及存档格式保持现有行为，无客户端文件或支持组件变化。

定向回归 `tests.test_wardrobe_apply_reply` 使用真实库存、衣橱事务及自有临时库，覆盖两件变更、空登记 map、物品状态与完整登记保留、精确回执重放、冷读初始化及批量末项失败回滚。测试需要锁定运行资源；不等同于自然鼠标点击或多人实战验收。
