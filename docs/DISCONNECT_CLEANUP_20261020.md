# 断线清理异常与取消保护

坐骑断线持久化遇到 SQLite 写锁时，原 Application.release 会跳过之后的世界/计时/playing 租约清理；旧连接无法完全释放，重新选角可能被误判为账号仍在游戏中。拆成两次 worker 调用也使取消发生在持久化期间时丢失后续清理。通知任务收尾被取消还会跳过业务清理和 socket 关闭。

本修复仅调整两个服务端文件的清理链：原有坐骑、计时和会话释放放在一次串行 worker 操作的 finally 链中；单个 shield 任务保护仍在队列中的清理。外层取消立即传播，真实持久化异常继续向调用方或事件循环异常处理器报告。FriendsSession 只释放属于自己的 playing 租约，transport 的嵌套 finally 覆盖通知收尾、业务释放和连接关闭。

无 schema、存档迁移、经济规则、客户端脚本、Hook、配表或启动器变化；不将失败写入冒称提交成功，不自动重发或回滚玩家数据。世界断开自身发生异常时，仅保证匹配租约释放及 transport 关闭，不宣称所有世界内部状态均修复。部署仍由维护者按独立备份和冻结产物流程执行，Git 提交不自动部署。

源码测试不需要运行资源或玩家库：`python -B tests/test_disconnect_cleanup.py`。临时合成 SQLite 数据核真实锁失败后的存储原样、异常可观察、开始与排队取消、通知 gather 取消、旧会话不删除新租约及连接关闭。GUI、自然玩家、多人和完整 SDK 边界不由这些测试代替。已审本地与线上源码的原有渠道差异保留，main 使用本地变体。

运行源码保持已审冻结候选的精确 LF 字节；原父版使用 CRLF，审阅时可用 `git diff --ignore-space-at-eol` 查看实际清理改动，不为缩短 diff 再次改动交付文件。
