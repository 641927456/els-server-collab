# 34320静态控制器组队退场

34320组队退场原本逐成员进入单人控制器处理，而单人准入只接受单一所有者，导致原生7523、7524、7513控制器报文不能完成共享房间同步。新增有限接收器核对房主原报文、已准入成员、当前租约、房间代次及原始出生元组，在同一数据库事务中记录各成员进度，并在提交前编码通知及检查有界消息队列。

客户端的AI、动作、计时、界面和原始UID映射继续复用。接收器不改编号、不强制完成任务或开门，也不发材料、经验或奖励。7513结束控制器与7511前驱的原始先后顺序均保留，服务端按已经接收的事实保护阶段转换。

运行修复为四份源码。Git主干缺少运行父版已有的前驱查询入口，因此最小移植为五份源码：在第五份`dungeon_flow.py`补两个必要查询调用。Git原有95条通用控制器规则及其处理函数保持不变；三个34320来源置于共享接收器专用集合，未合并其他待审PR或复制运行父版的全部113条规则。

已保存的分解证据包括来源与编号元组、单所有者真实存储事务及第二成员拒绝回滚、共享房间内存路径、真实编码器和消息队列边界。Git检查只验证源码、隐私、格式及协议基础；CI中的运行检查若显示SKIPPED，不能计作运行或实机通过。

全部成员真实SQL正向、原生组队报文及自然完整路线仍未验证。组队Boss材料的受益资格、抽取分配和共奖属于独立缺口，本修复不开放该功能。线上、本地部署以各自独立交付回执为准，Git提交本身不部署服务器。
