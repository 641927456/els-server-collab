# 商城请求积压修复

正常高频请求反复读取完整角色与库存，服务端处理落后于到达速度；实际公网商城回包在约51秒后才到达，超过原生20秒等待期限。

服务端在一次 Application.call 内复用未变化的已提交读取；SQLite data_version 检测任何其他连接的提交，立即作废缓存，操作结束关闭只读观察连接。缓存不跨请求持久化、不持有读取事务；角色/账号/数据库/投影分开，返回值隔离调用方修改。出席资格检查只读取现有身份字段，保留账号启用、角色归属、阶段和playing租约检查。业务事务、回执、时钟及通知体保持原流程。

五个服务端文件已备份交付线上与正式单机。V30客户端与启动器保持；后台自有QA连接公网并等待180秒后，原生商城窗口和商品正常显示，完整175901字节目录约0.382秒返回，购物车和保管箱回执完整。测试隔离三个SDK启动返回边界，不声称对方自然SDK启动、全部购买或多人实战验收。测试QA已禁用。
