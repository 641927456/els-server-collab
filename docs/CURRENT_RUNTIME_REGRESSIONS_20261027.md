# 当前运行回归与旧套件分类

Issue #558，父为 #556 性能候选。运行源仅补双端 `LocalSession._capture_luciel_dungeon_hp` 的空角色兼容。旧无 Characters 的协议模式返回前清除旧 LuCiel 捕获；已有 Characters 却返回空 owned snapshot 仍拒绝，真实 LuCiel 的三个 span、当前 UID 和原生浮点保持严格。

旧套件的失败不全部代表当前线上漏洞，也不从 CI 隐藏后宣称已全修复：

| 范围 | 确认原因 | 本次处理 |
| --- | --- | --- |
| 旧副本空角色调用 | LuCiel 专用采集器直接下标 None | 最小兼容保护，新增三项专门测试 |
| TLS 角色选择 | 旧 28 封套缺 performers=(0,) | 更新夹具；新增错误封套仍拒绝的真实 TLS 测试 |
| TLS 分包继续 | 旧 5BF 空载荷不符合现行两个 i32 游标 | 正常夹具使用原生八零字节，保留生产拒绝 |
| TLS 创建容量 | 16 个角色同一天超过现行四个/日 | 夹具按受控四天创建，另外断言第五次当日拒绝 |
| 旧静态副本全量重放 | 旧无持久化/活 Application 的 session 不满足当前疲劳绑定，部分剧情/动态路径已有新资格 | 保留旧原测试和失败，不关闭资格、不将全部 catalog 路由称为当前可直接入场 |
| 旧 B2 整字节相等 | 后继 NPC 输入的类型/等级已有正式变化 | 保留原失败；当前 finite HP/Hero 原生输入测试分别验证，不回退正式输入以满足旧断言 |
| 旧跨城/组队等 | 后继准入/资格和同步流程未在老夹具中完整表达 | 保留为独立待改覆盖，未把通过当前双账号烟测扩称全多人实战 |

旧 TLS 原父与性能候选同为 12 例/9 错误，失败 ID 无新增。修正部分夹具后剩余失败继续保留。旧副本此前 252 错误/1 失败只表示当时 main 的精确比较；本次在实际 Clock 引擎上继续调查到空角色保护之后的疲劳资格拒绝等情况，不把不同基线的数字相互替代。

`tools/verify_current_runtime_regressions.py` 验证仅一叶差异及完整源哈希。加 `--with-runtime` 使用临时自有库/证书/双账号，跑当前合法登录、双方各 128 次辅助报文、只读库存栅栏、排队遥测、独立连接撤权、错误原生封套拒绝，以及现行 committed-read、称号、HP/Hero 和专用保护集。具体命令与跳过项逐通道输出；不运行全旧 Friends/Routes 并冒称其全绿。

测试证书复用现有工具，构建机安装 `requirements-test.txt`；没有新生产依赖、客户端、经济规则或存档恢复。所有测试资源和临时视图在项目内创建并收尾，玩家数据不进入测试。正式安装还必须从届时真实新父叠加本项和 #556，保留后来正式增量。
