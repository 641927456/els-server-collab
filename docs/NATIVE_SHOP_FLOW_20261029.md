# Signed shop support delivery

V40 recognized one fixed catalogue length. Current catalogues can change, and
duplicate responses could repeat native UI initialization. This delta validates
the complete native body and product map, tracks role/session/UI ownership,
coalesces requests, and handles late responses after close.

One additional probe at original313ABCE changes CPU ECX0 to2 only for a qualified
duplicate/closed/invalid owned invocation. The original TEST/CMP/JNE reaches its
own cleanup. It retains original parsing, wait consumption and map handling;
it does not write the native ready flag, state578, PC, or original EXE/KOM files.
The v1 close-late counterexample and v2 ineffective Frida PC write remain rejected.

The component backend is the accepted ONLINE Force/GuildAgit version. LOCAL
uses its own current/bundle path and receives the same three support files in
a separate immutable runtime. Its original narrow UID bound is recorded as a
known parent difference. All unrelated V40 sources, DPAPI/update/local-mode
capabilities, Python/Frida libraries and five native support sources remain.

`launchers/friends-v41/source-manifest.json` maps all16 text build inputs. Thirteen
reuse existing exact Git sources; only Program payload hash, updater version and
the signed component manifest change. The seventeenth resource is the exact
retained `ElsFriends.Ruben` PNG from the publicly signed V40 EXE, with its SHA
and size pinned; binary resources and official EXE/ZIP artifacts stay outside Git.
It can be extracted via .NET Assembly.GetManifestResourceStream after verifying
the parent EXE digest. The launcher icon remains the existing locked asset.
No publisher key, negative signed test data or private V42 fixture is included.

The isolated signed reader verified1764 components,914 old-file reuses and850
changed downloads, repeat reuse, corruption/truncation rejection and retry.
The actual old V40 update contract accepted the new signature and tested cache
activation/rollback. Actual public V41 artifact downloading is a later publication
gate, separate from those isolated checks. Default CLR4 production paths were
checked independently of the deliberately shortened private test directory.
