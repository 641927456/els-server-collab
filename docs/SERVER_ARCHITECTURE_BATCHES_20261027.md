# 有界周期批次与纯准备分工

Issue #569。从 `server-risk-current-local-roles-20261027-v3` 双端完整源继续，仅变更 application、transport、accounts_gateway、storage/accounts 四个已有叶，新增 periodic_scheduler、preparation 两叶。旧冻结源、LOCAL 子角色快路、票券与角色刷新及所有非本批文件保持原 SHA。配置、客户端、存档、旧交付事实不入本次源码变更。

## 周期调度

原先每连接每 50ms 单独提交；新调度器按单调时钟 deadline 选择当前空闲连接，最多 16 个一批，最多一个周期批次在业务执行器中等待/执行。不补跑已经错过的空周期。每个连接的 operation 锁从周期入队前持续到回复发送结束，断开先等待已开始的周期工作，再执行原持久化清理。慢 drain 只占其本连接，不使其他连接的调度等待它。

每个成员仍独立执行 committed-read scope、活动时钟 observe/after_reply 和原启用检查。同一批内同一普通副本房间只轮询一次，保留原 room deadline、250ms 节流、成员通知顺序及请求触发的轮询；野外首领、组队挑战、每秒过期/称号/共鸣路径保留。线上 50ms、LOCAL 1s 的原检查周期保持；这是调度目标，不承诺拥塞或长业务下硬实时到达。

隔离 64 连接测试中，第一轮 64 次单独提交合为 4 个最多 16 成员的批次。此为受控调度测试，不能当作自然多人吞吐或客户端 RTT 验收。

## 只读与计算准备

仅注册/口令登录的 salt、只读凭据查询和 scrypt 进入两个独立准备线程，最多两项实际在途，无额外排队。取消等待不会提前归还实际仍在运行任务的容量；饱和沿现有 `rate_limited` 回复。它不执行 LocalSession、业务投影、经济写入或跨请求角色缓存。

速率限制、配置和 registry 选择仍在业务线程。登录准备用独立只读 autocommit 连接，关闭后再算 hash；最终在业务写线程 BEGIN IMMEDIATE 内重新读取账号 ID、名字、enabled、salt、digest，并核 registry/文件身份，拒绝准备后禁用、改密或文件替换。注册最终重新核容量/重复名字/开关。令牌签发、过期清理及每账号最多八会话保持原事务规则。

同机自有临时库各 20 次实际 scrypt 登录期间，其他无写业务 fence 的等待 P95 从 45.425ms 降至 0.196ms；未触及生产库，不代表玩家网络时延。统计仅记录固定计数/耗时，不记录口令或凭据。

## 验证与剩余风险

双端重建完整引擎，覆盖当前 TLS 双账号辅助突发、即时撤权、错误封套拒绝、子角色、称号/HP/Hero 输入、取消清理和读取栅栏；新增慢发送隔离、64 连接批次/公平、关闭等待、独立失败、读 scope/时钟/房间去重、有界准备取消及注册登录竞态。另保留原注册 TLS 三项。旧全路线资格/故事/疲劳夹具缺口不降低业务守卫来消除；自然 GUI、多人峰值 RTT、完整自然战斗保持独立边界。

仍需优先定位的卡顿风险：

1. 单个经济 handler 或 SQLite 写锁等待仍可占用单写线程约 10 秒；按分段计时定位具体事务及 SQL 计划后缩短持锁段，不能盲缩 timeout 或并发经济写入。
2. 单批最多 16 成员仍可能被其中一个慢周期拖长；已有单成员计时，后续按实际耗时决定是否降低批量或拆特定周期事务。
3. 冷角色投影/大 DTO 与静态资源首次加载仍可能昂贵；下一步逐场景抽纯 decoder/serializer，提交前核 UID/lease/revision，避免过时经济回复。
4. 极端磁盘停顿下关键日志的同步溢出保护、原生 relay/网络排队及客户端绘制仍可能影响体验；后台准备线程和服务端 drain 指标不能证明这些已解决。

没有新增数据库、表、安装 DDL、微服务或更多业务写 worker。默认已验收源指针只在双端正式核收后更新；Git/CI 不代替安装事实。
