# 已保存物品的有限读取兼容

问题 #454。旧库存读取器会拒绝30603已保存的两个属性和 identified=true，以及130208已保存的数量3实例。后续独立修复能够合法产生这些形状，因此先交付纯读取兼容父版，使这些存档在受保护代码回退后仍可读取。

仅修改两个现有函数：

- identification_ui.validate：30603绑定当前客户端SHA及物品记录a53341030d3cd98636188c44955a5715ff69fa52775eacb9453da529db93699b，仅接受两个整数且各属于已核41个OptionID。普通业务require_template不变。
- inventory_items.validate_item：130208仅在metadata2/bag4的精确原生轮廓下，绑定记录def908d624a81559b11442227ffde76f36174a71b6ca42d82d35f89ed02e4cb1并校验原生上限1000，允许已有数量1～1000读取；30603的identified=true使用同一有限双属性读取校验。

全局TEMPLATE_MAX_STACKS[130208]继续1，正常grant_items仍分配单件，不合并已有超单件实例。没有新模块、数据文件、schema或安装DDL，没有批量存档迁移；旧438/43A资格和原生item_body/byte34D写法不变。本项不接通鉴定、提取或任何新增来源，不增加概率、费用或游戏功能。

来源为当前固定客户端物品记录与既有已核属性ID表。私有双渠道各5项验证通过：实际已保存双属性30603与数量3精髓经SQL读取及完整原生记录编码；41属性及类型/数量非法边界；精确精髓数量1000与溢出/错误轮廓拒绝；工厂仍分配单件、既有堆叠不合并；旧438/43A仍拒绝且SQL不变。两渠道完整候选包检查通过。独立审查以逆向替换AST确认两函数以外与各自实际父版完全相同。

公开源码CI、5项账号键位测试及隐私守卫在本PR另行执行。提交与合并不表示正式部署；维护者另核实际双父、备份、正常drain、代码优先恢复、观察及零经济写入的公网登录/冷读验收。自然GUI与后续写业务没有据此通过。
