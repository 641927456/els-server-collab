# 普通组队中的本人复活与同房同步（Issue #238）

普通 2～4 人队伍在副本 `30000` 的 `stage 0` 完成加载后，每位成员可使用自己已有合法来源的角色余额 C 复活本人。服务端核验当前账号、角色、租约、房间成员及死亡阶段，成功只扣本人 1 次；死亡完成的 AC 和复活的 162 通知同房成员。一次复活的明确出生点键由服务端选定并原样广播，复活者与观察者接收相同落点，不各自随机。

本增量是候选源码，**尚未安装本地或线上**。交付前检查发现游戏仍在运行，安装按保护规则等待；Git 合并也不代表已经部署。原有已安装的来源箱、角色余额保存及单人范围继续保留，启动器没有新增载荷。

## 最小服务端改动

运行范围为 6 个文件：既有 `known_resurrection_flow`、协议和存储的三文件增量，以及来源锁定的地图读取模块、地图 JSON 与 manifest 三个新文件。地图仅准入 `30000/stage 0`，绑定当前同版地图定义、路线来源和 12 个已核 LineMap 出生点键。

房间成员、加载屏障、阶段或队列发生变化时拒绝操作。通知先在私有队列副本中完整编码并检查容量，成功后才提交本人余额和本次生命回执；准备失败时保持余额、旧回执和其他成员状态。共享房间使用既有 UUIDv4 房间种子划分生命回执，不改变每人奖励链的 UUIDv5 标识。

客户端继续承担原生 HP/MP、复活动作、效果、显示和计时。服务端没有新增共享复活石池、队友代付、每日免费次数、自动现金支付、通用地图次数或治疗模拟。

## 已有验证与边界

五项私有验证通过：正常双会话复活、同一成员第二条生命、成员退出、真实断线重登，以及队列溢出的事务保护。其中队列溢出是明确标注的受控邮箱负例，不是从 TLS 发送的越界报文；其他场景使用两条实际鉴权的回环 TLS 会话。夹具只使用自有临时库和明确的等级/190556 来源预置，没有修改游戏 HP、死亡阶段或怪物状态来制造通过。

实际 TLS 仅覆盖 2 人，3/4 人组合只过资格源码审查，尚未实测。这批证据覆盖本人扣费、回执、AC/162 同房消息与同落点、旧连接拒绝和重新鉴权。最终收口到 stage 0 的来源范围另由独立审查核收，不把原候选中未实际执行的其他阶段算作通过。

新增的两项便携存储回归已由维护者执行通过，分别确认准备回调失败时，空账本和已有生命回执两种状态均不增加扣费或账本记录；旧成功方法没有重跑。这不是完整回归或客户端界面验收。

新共享 UUIDv4 记录的受控存储兼容验证已通过：新写入器实际提交 A1、B1、A2 三笔生命回执，经 SQLite backup API 生成私有副本后，精确旧版计数读取器读回 8/9；读取前后带类型的全行及 schema 保持一致，两个临时库已销毁。此结果仅覆盖旧计数 snapshot，不代表 outer 2A、完整角色 profile 或正式回退演练。

其他阶段和其他副本的来源仍待核：本轮明确授权的八资源离线分析在首个资源变换调用遇到 `UcError()` 后停止，其余七份没有尝试，未恢复任何明文。不能用文件名规律把后续世界脚本对应的 LineMap 当成已证，也没有自动重试或扩大仿真范围。

自然客户端界面、真实玩家多人实战和其他地图未验。现有私有协议与事务结果不替代这些验收，SDK仍在本轮范围外。
