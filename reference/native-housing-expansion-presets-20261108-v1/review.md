# 家园闭环差异审查

结论：21 个服务端文件的候选通过本会话差异审查；尚未安装。对照实际 V108 父版逐文件核定，六个新增模块、四张惰性业务表；不新增客户端支持文件或 Hook。

本次补齐家具栏 560 格、六种已批准 50 ED 扩张券、三层／五阶段／四预设、原生预设保存改名应用、上层楼宠物垫及四条家园业绩。原生 NPC 商店四种普通家具曾被箱子来源校验误拦截，现通过当前商店原售价、角色及原 SQL 事务绑定的来源购买。普通泛发仍拒绝这四种家具，混合购买按来源分组，同一事务扣款、造物、编码及回执提交。

审查发现并修复两处问题：NPC 家具缺少合法购买来源；首版修复在验证商品前读取注册字典，可能把未知商品的明确拒绝变成 KeyError。最终候选已将普通商品字典读取放回商品准入和价格验证之后，相关拒绝及无增量测试通过。

影响入口为原家园布局处理、业绩事实投影及 NPC EA 购买。父版文本引用统计：共享来源发行器涉及 20 个模块，家园入口涉及 2 个模块、房间状态涉及 5 个模块、业绩计划器涉及 2 个模块。来源发行器仅增加 npc_trade 种类；其余种类逻辑不变。家具来源只作用于既有四种箱内家具，其他购买仍不携带这份来源。

已核身份／当前入场代次、楼层所有权、家具 UID 跨楼层唯一、单宠物垫、库存数量、预设阶段和槽位、事务失败无增量、预提交编码及回执重放。预设描述保留原客户端产生的几何数据；应用时由原客户端选择当前拥有的实例，935 保存再验证实例。业绩按角色实际布置数量和账号历史最大值计数，不按保存次数或多角色相加。

验证包括既有相关存储和原生编解码结果、原 Game 保存／改名／冷读／应用预设／935／第三层角色和返回、上层楼宠物生成取回及楼层返回。新增 NPC 七项经济测试通过，覆盖原生价格、混合来源、未知商品、错误商人、余额不足、满包、资格变化回滚、回执重放、200 件正常 NPC 获取及业绩。最终 21 文件在实际 V108 组件上经 App/TLS EA/EB 购买四件家具，随后原 Game 冷登录读取正确数量及原房间、预设和宠物垫。

失败原记录保持：早期预设应用测试错误地要求完成后操作状态不复位；原函数会立即复位，已按实际模型与存档纠正。一次原生调用系统异常、诊断文件共享冲突、QA bool 参数错误、端口竞争和取消的诊断轮次均未改记成功；后续从实际已提交的自有状态继续，未重发经济请求或恢复数据库。

存档使用新楼层表并保留旧 floor0 表只读兼容，旧位置格式仅在历史读取时保留。首次新增楼层之后旧代码不能读取该范围，候选启动后必须保留新读取器并前向修复；禁止以恢复玩家或账号库回滚。来源账本沿用已有 raid_reward_sources，不新增该表定义。

范围边界：自然 GUI、200 件家具的自然摆放和多人实战未宣称验证；访客／邀请、音乐、留言簿及家具权益不在本批闭环范围。业绩累计达到 49 类来源、322 条定义，余下 11 类来源及 53 组缺失原奖励保持未完成、暂缓发奖。本轮完成 Git、双端／启动器安装及进度更新后按用户要求收尾，另列剩余功能表。
