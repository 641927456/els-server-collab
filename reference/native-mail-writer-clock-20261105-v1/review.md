# 邮件写锁后取时修复

邮件领取/读取/删除及普通玩家发信在等待 SQLite 写锁前采样时间。真正取得锁时已到期的邮件仍可领取 ED，已过期的道具仍可进入邮寄托管；刚到期的普通玩家附件则可能被误判为不可删除、暂不进入退回流程。

两个源码文件只将四个写入口的时间采样移至 BEGIN IMMEDIATE 与原身份复核之后。保持原生邮件 expires_at <= now 与道具整秒 expires_at < now 的既有差异，保留显式 now 参数、身份/收件人规则、手续费、原子扣发、幂等和预编码，不改保管时长或其他经济数值。查询快照和管理接口没有随静态搜索批量改动。

八项真实隔离存档用例均以第二个 SQLite 连接持写锁，再在另一线程进入实际业务；到达 BEGIN 后跨越边界并放锁。父版复现到期邮件错误领取 900 ED、错误读取及到期附件错误邮寄。修复版拒绝这些输入，整库转储一致；邮件在期限前正常领取一次，道具在其最后有效整秒仍可寄出、UID 和期限保留，其他已有物品不变。过期玩家 ED 删除生成且仅生成一封退回托管，收件人零收入，发件人两次领取只增加一次 900 ED；预编码故意失败时退回及删除全部回滚。

第一轮玩家附件夹具错误地断言发件人没有其他物品；角色初始化已有物品，所以该断言失败。已改为逐项保留其他物品并仅核当前附件离开，新的基线与修复结果使用不同证据文件，旧失败不作为业务通过。

测试只使用 G 盘自有临时账号/角色及库，退出均清理；无生产库写入、客户端或新表变更。此归档尚未安装，不声称自然 GUI；作者自审不代替精确 head 的人类主干合并审批。回归设置 ELS_FULL_SOURCE 为完整父版运行树后分别运行两份 test 脚本；--baseline 复现父版结果。
