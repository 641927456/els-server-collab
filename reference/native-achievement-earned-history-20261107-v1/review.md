# 业绩历史来源增量审查

V92 已接通 14 类来源、106 条业绩。本候选仅改变历史读取、现有条件分派和对应回包后的同步三个文件，增加 16、23、25、43、44、56 六类来源，覆盖到 20 类、131 条。未安装、未更新线上得分，不代表其余功能完成。

| 来源 | 复用权威记录 | 计数边界 |
| --- | --- | --- |
| 16 物品使用 | `inventory_action_receipts` 的 718 前后物品快照 | 当前原生条件仅引用 189800，按相同 UID 的实际减少量；712417、移动、失败不计 |
| 23 退出公会 | `native_guild_operations_v2` 的 290 / 291 成功回执 | 只计算目标等于请求者、非踢人的正常退出；踢出和解散的原业绩语义尚未查明 |
| 25 获得公会名誉 | `native_guild_quest_facts_v2` 的活动 100 | 原业务在上限处理后实际入账的整数，累计保留周历史；其他任务活动不计 |
| 43 使用共鸣重置币 | `resonance2026_reset_receipts.consumed_json` | 复用原扣物入口的三种币，每个实际消耗单位计一次 |
| 44 使用共鸣重置卷轴 | 同上 | 复用原扣物入口已准入卷轴集合，一次类别重置消耗一张；不按返还点数计 |
| 56 公会收获 | `native_guild_operations_v2` 的 803 / 804 成功回执 | 每次实际收获一块地计一次，与产物数量无关；种植、移除、浇水、失败不计 |

读取器不创建表、不写源事务、不接收客户端计数。只有原有业绩保存入口按实际存在的表懒建三个索引；既有库存回执 `(kind,owner)` 索引直接复用。账号来源通过现有角色归属或回执中的事务账号限定，原有单调进度、完成记录、展示和领奖逻辑不变。原事务回滚没有源记录，重放使用既有主键记录，不增加数量。

直接调用者为 `achievement_profiles.reconcile`；其三个运行入口仍为原生 6BE、冷登录／回城以及已存在的回包同步。新增 719、612、614、291、804 等对应触发。名誉还覆盖疲劳通知、任务领奖、浇水和讨伐报名；其他既有生产者可由正常 6BE、回城或冷读恢复，不新增跨状态处理分支。生产者仍掌管身份、资格、扣发和原事务。

已按同一最终三个源码 SHA 验证：三个实际 Application/TLS 场景（正常退出与踢人区分、真实收获及名誉、实际共鸣币／卷轴／导师药水消耗），三个生成式记录测试方法。包括账号边界、旧周记录、正 UID 边界、数量边界、失败无增量、重复查询不重复完成、另角色冷读共享完成且展示独立。所有私有测试库、账号、证书和日志随本次隔离临时目录正常清理。生成记录测试不冒充真实业务请求，TLS 测试不冒充自然 GUI 或原生 Game。

保留的失败均未改变业务断言：记录测试最初未调用实际启动时的成长物品注册；TLS 发放最初缺导师奖励的受限来源；农场名誉夹具最初误取浇水而非收获参数；药水脚本最初重复使用已经耗尽的同一实例。分别补齐正常注册、使用原奖励向量及来源验证、修正收获参数、读取当前仍拥有的实例后，相关失败场景已通过。失败 JSON 留在原分析目录，未上传私库或日志。

53 组原奖励继续查证、暂缓发放，不使用替代药水。本候选没有增加道具获取渠道、奖励、价格、概率、Buff、客户端 Hook 或修改 EXE／KOM。旧版本尚未保存的源历史不猜补；退出的踢人／解散语义、其他 40 类来源、部分原奖励变体和自然 GUI 继续保留待办。
