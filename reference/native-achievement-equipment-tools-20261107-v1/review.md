# 装备与副职工具业绩来源

本候选从已交付 V93 的三个文件继续，增加六类权威历史来源：强化到指定等级成功（32）、魔法石实际消耗（45）、神秘的艾尔之球（51）、神秘的艾尔烧瓶（52）、神秘的艾尔铁砧（53）及魔力石实际消耗（60）。累计为 27 类、164 条定义，其他 33 类仍待接通。候选通过隔离测试，尚未安装。

32 读取普通强化与铁匠强化共同提交的 5FF 库存回执，按同一 UID 的实际等级增加、最终精确等级累计；219 强化卷轴、无变化、降级、初始化及破坏均不计。45 读取 1C4 实际扣除的道具单位数，因此一次两孔操作计两次。60 同样读取 6E7 实际扣石单位数：付费预览扣石，应用预览结果不再扣石，不重复计数。16 的原有导师药水消耗复用同一数量比较。

51/52 分别读取已提交的 705/707 特殊工具回执，不将普通制造或 9AE 烧瓶奖励领取混入。53 读取 `profession_anvil_receipts` 的账号归属，按已提交操作累计，不从当前锤子余额、倒计时或客户端次数推断。新增一个延迟创建的账号索引，不新增表或启动／安装 DDL。库存回执复用已有 `(kind,owner)` 索引。

入口身份和所有资格、ED、道具、概率、事务、操作 ID 均沿现有业务处理器，未作修改。计算使用认证账号及服务器历史，客户端不能提交业绩数值。实际业务 ACK 后立即同步；冷读和另角色共享沿原入口。奖励表、客户端资源及原 EXE／KOM 未改，53 组原奖励继续暂缓，不用替代药水。

审查发现候选最初用 JSON 关联扫描逐件匹配库存，128 条、每条 65 件物品的隔离样本耗时约 183ms。改为每条快照只解析一次并按 UID 建表，同一输入约 5.65ms，结果一致；这只是该隔离查询的测量，不代表线上延迟或容量。强化查询也使用同样的单次解析方式。数据按游标逐条读取，不把整个账号历史一次性加载到内存。

四个测试方法覆盖 155 个生成样本及无来源表读取；真实 Application/TLS 场景使用明确标记的旧历史、等级、ED、材料和强化满槽夹具，加六类正常操作完成 185/205/304/309/314/355。覆盖两孔耗石、预览后应用只计一次、逐次即时 6C0、无材料／冷却拒绝、事务编码失败回滚、同操作重放不增量、账号隔离、重复查询、另角色冷读共享，以及 314 缺原奖励两次领取均拒绝且不修改存档。隔离服务、连接和临时存档在测试结束关闭清理；未运行自然 GUI 或原生 Game。

仍未计入闭环的两项：30 的普通强化次数还需核清卷轴计数语义；34 的煮鸡蛋购买缺有效道具读取器及温泉小贩限时购买入口。后者不能仅接一般 NPC 购买 ACK 就声明完成。最新官方温泉说明为每五分钟出现小贩，十秒购买窗口；本批没有改动此入口。
