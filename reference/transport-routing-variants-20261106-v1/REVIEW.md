# 代码审查

原缺陷族：manifest核对全员，relay_target再次调用manifest，发布器又对每个发送者的每个目的地调用relay_target。婚礼已在父候选修复；本次核对摄影棚和赛车的两个同类入口。

photo_zone_flow.routing与FriendsRacing.routing分别执行各自原_capture/current谓词。RealtimeState.publish按当前房间对象在本次worker调用内复用结果。原注册状态读取仍在enabled_snapshot内；旧会话、错误阶段或绑定变化使该房间无可发布路由，下一次合法发布重新核对。所有结果都从已入场成员生成，无请求可提供额外成员、UID或端口。

摄影棚使用实际当前ports并在主房主离场后保留现存槽位。赛车保留原成员manifest的全部端口，但只给仍属于当前房间的成员生成路由，离场者不再有收发权限。没有把赛车历史席位压缩成新索引，也没有引入持久缓存、权限旁路、重试或新的超时。

变动范围3个既有文件，受影响调用为共享路由发布、直接manifest/relay_target以及摄影棚/赛车各自的成员核对。经济、存档格式、比赛公式、奖励和资格未修改。相关实际测试与具体边界见verification.json；未发现本次变动中的越权路由或离场者保留权限。

失败保留：赛车首用例的摄影棚退出夹具reason0不适用于赛车，在发送前断言停止；通过当前原生2B228D0→virtual270→1AB2B10和原DA2F50 writer核实0x72并修正测试，只续验离场范围。原先已通过的6人核对/转发按同3文件哈希复用，没有放宽服务端断言。自然Game、自然GUI和比赛结算不属于这次验证。
