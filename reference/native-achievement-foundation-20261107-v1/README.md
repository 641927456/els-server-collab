# 业绩可信来源与共享角色状态候选

原有业绩普通请求、奖励邮件、预览和角色状态没有闭环。本候选接通普通 6BE／6C1／6C9，账号共享完成记录、每角色展示、当前角色奖励邮件；修复普通角色刷新、任务、转职、城镇、公会领地、住宅及副本／对决／婚礼 FullUser 数据清空业绩状态的问题。

当前接通 14 类可信来源，覆盖 106／377 条定义：副职、共鸣、公会邀请拒绝、交易、普通发信、宠物／骑宠、公用银行、称号、钓鱼尝试／指定钓获、宠物远征完成、转职阶段及超越角色数。另有 46 类来源待接通，不能将本候选标记为全套业绩完成。

用户决定为“继续查原奖励，暂缓缺失组发奖”。原奖励已有 101 组来源引用，53 组仍缺原始物品／数量。本候选只接入其中 50 个已有物品读取支持的组；另 51 个已引用组还需物品版本／读取与使用资格核对。未配置组明确拒绝领奖，保留未领取状态，不替换为药水。读取支持也不等于全部物品使用、期限及奖池均已完成验收。

业务源码在 `source-v1`，相对冻结 V87 服务端的文件与 SHA 见 `evidence/reviewed-source-files.json`。21 个文件中 20 个有增量，未改动的签到预览 JSON 是私有独立载入依赖。当前只是已验证候选，尚未安装、未合并主干、未增加线上进度分值。发布时必须从当时三端真实父版选择性整合。

私有 App/TLS 已验证账号隔离、并发领奖与附件提取、原子回滚、重放、实际交易和发信、宠物／骑宠注册、48 格公用银行、有效称号、真实钓鱼结算、普通远征及转职／超越道具使用。历史计数、初始职业、道具获取和等待时刻等夹具在结果中明示。原生离线读取交叉验证完整 Unit 和四类成员数据。

原客户端隔离检查 V17 通过零积分界面、一次六条完成通知、两次完整 D9 保留积分和展示、原生重新打开。游戏 67.839 秒／后端 89.505 秒，143 帧、两次快照、两次完整复制；原文件及输入桌面未变。V15／V16 的测试器失败保留在分析目录，未改成通过。没有控制玩家输入或进程，未修改原 EXE／KOM，也未声称自然 GUI、自然成长或自然多人实战已验。

可以用 `python -B verify_candidate.py` 检查归档和原生核收输入一致性。测试脚本需要项目已有的私有原始资源与 V87 完整运行环境；App/TLS 测试通过 `ELS_ACHIEVEMENT_RUNTIME` 与 `ELS_ACHIEVEMENT_QA_TOOLS` 选择同一套环境。默认路径为原分析目录，不在 Git 中分发运行库、客户端、凭据、玩家库或原始日志。测试创建并清理各自独立临时库。
