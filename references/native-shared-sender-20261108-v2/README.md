# Native sender serialization and shared town observers

Five support-file changes address two confirmed native defects on the exact supported DX11 build. Frida 17.23.3/Gum revision `1208a1266e9d28e6c958b6a167b6d944ebefaf47` allocates invocation data for two listeners per function, while the retained runtime registered five sender observers and could add a third town-frame observer when entering the ED shop. A sender-entry-only critical section also misses NativeFunction-origin sends from another intercepted frame. The owned host reproduction produced 79 duplicate counters in each 256-send scenario. These findings establish defects in the candidate paths; they do not prove which defect caused every historical player disconnect or duplicate sequence.

The candidate consolidates the sender and town-frame handlers into one physical JS listener per address, retaining separate invocation state and dynamic detach behavior for each logical observer. Complete artifact and ED-shop support remains under its original feature flag in the main Script. Original native methods still own catalogue decoding, UI changes, character calculations and economic requests.

Native `replaceFast` wrappers acquire serialization at the original crypto constructor and release it at entry to the matching context destructor, after the common sender has incremented the counter and queued the packet. A TLS context stack owns the critical section. This placement covers the verified NativeFunction-origin path. The original destructor runs after release. The CModule, trampoline cells and ready event remain rooted for the process lifetime; the launcher exits its owned child before detaching. Live hot unload or player-process attachment is not supported.

Inputs are pinned to original EXE SHA256 `6c6b51809aec90f9b717a9e55d679f221315a6296d69da80510e3456423a1709` and the existing reference snapshot. The delta is based on V106's actual complete 2,873-file manifest and preserves the eight intervening achievement/guild/power changes. No server business code, private configuration or database schema changes are included. Original EXE/KOM files are not patched or shipped.

Validation uses the exact candidate file hashes in `delta.json` and `evidence/composition.json`:

- Eight-thread native host with common and frame-origin NativeFunction producers: 240 sends, zero duplicate counters, ordered queue. False return, C++ exceptions before/after counter advancement, throwing destructor, nested context and unmatched destructor paths all finish with active lock count zero. LastError remains transparent. All 22 generated nonleaf call return PCs have runtime unwind coverage. Actual C++ unwinding crosses the wrapper and reaches RAII cleanup.
- Injected second-replacement failure: a real native waiter blocks before `finally`, completes after the ready event is signaled, and the retained original cleanup remains callable.
- Original 19-byte destructor entry/trampoline and exact tail chain execute in an owned host on the empty inline-string path. The nonempty free branch is inspected statically, not qualified by that host case.
- Exact shared dispatcher with real Gum: independent native getter forwarding and per-observer state, add-next-invocation, detach-before-turn, onLeave-only callbacks, logical exception reporting and dynamic shop-listener cleanup all pass.
- Owned original client on a temporary authenticated server: existing Quick Start creation reaches town. Normal ED-shop toggle opens, consumes 3,534 native products, initializes the original UI, and closes normally. Sender callbacks are 285/285, field callbacks 1,918/1,918, crypto/cleanup 290/290, dynamic field observers peak at four and return to three. Both target addresses retain one physical JS listener. No protocol or Frida errors occur. The original EXE is unchanged, and the owned process exits before detach.

Two earlier owned fixtures are retained as failed prerequisites rather than counted as shop passes: a normal new character entered the compulsory first dungeon; the first Quick Start run toggled on the first town frame and did not issue a catalogue request. Early availability timing is inferred; the failed run did not capture that bit. The final fixture waits two seconds after the first owned town frame and records the native state. The production candidate did not change for that correction. Raw traces, private consoles and temporary databases remain outside Git; only derived evidence is archived here.

`original-sender-EH.json` records the decoded MSVC FH4 graph. All 43 applicable C++ call unwind chains reach the matching destructor with stack object offset `0xd0`. The prologue/frame calculation and exact destructor tail chain are recorded separately. This does not claim hardware-SEH recovery or prove arbitrary native reentry after an outer counter has advanced but before its enqueue. The observed JS-triggered nested send occurs before the outer crypto constructor.

This archive supersedes the v1 native candidate on PR #951; v1 remains unchanged as historical evidence and must not be installed. Relevant successful unchanged-core results are reused. Verification scripts reference private G: fixtures and the locally installed compiler/Frida environment; they are source records, not a standalone redistributable game harness. No compiled fixtures, game image, credentials, player databases, raw packets or runtime logs are included.

At source freeze the candidate is not signed, installed or merged. Independent Hook review establishes technical review only. A new exact Git head still needs the repository's required approval or the user's explicit single-head exception, and the new native batch still needs publication takeover authorization before the designated publisher signs and installs it.
