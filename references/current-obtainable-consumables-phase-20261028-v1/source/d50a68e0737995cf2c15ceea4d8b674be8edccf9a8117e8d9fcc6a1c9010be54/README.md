## 服务端结构

当前使用模块化单体结构。网络连接由 asyncio 管理；默认本地模式沿用一个账号，朋友服模式按已认证账号创建隔离会话。业务操作进入串行执行队列，避免会话并发修改角色状态。数据库工作在独立线程中执行，不阻塞网络循环。

| 目录或文件 | 职责 |
| --- | --- |
| `els_server/__main__.py` | 生命周期、启动检查、停止信号 |
| `els_server/config.py`、`config/server.toml` | 严格配置校验、功能配置、超时与容量 |
| `els_server/transport.py` | TCP 连接、分帧、校验、顺序、背压、连接回收 |
| `els_server/port_probe.py` | 本地 UDP 地址探测应答，端口与 TCP 服务一同创建、回收 |
| `els_server/application.py` | 会话创建、单账号串行任务队列 |
| `els_server/protocol/` | 已验证的加密帧、消息和序列化布局 |
| `els_server/domain/` | 角色、背包、商城、副本等业务状态与规则 |
| `els_server/storage/` | SQLite 存档、交易与幂等回执、存档独占锁 |
| `els_server/observability.py` | JSON 滚动日志，默认最多 5 个 5 MiB 文件 |
| `capture_server.py` | 保留的协议采集实验工具，完整运行入口已不再使用它 |

根目录原有业务模块保留为兼容导入，实际实现只有包内一份。历史验证脚本仍能运行。

## 运行与配置

服务端要求 Python 3.11 或更新版本，以及 `requirements-server.txt` 中的依赖；本机已使用 Python 3.13 验证。客户端诊断启动器另依赖现有 `tools/pylibs` 环境。

```powershell
python -m els_server --config config/server.toml --check
python -m els_server --config config/server.toml --stop-file run/server.stop
```

手动运行服务端时，确保停止文件不存在。结束时按 Ctrl+C，或创建指定停止文件。整合入口会为每次运行使用独立停止文件，游戏退出后自动停止对应服务端。配置内相对路径按 TOML 文件位置解析，不依赖终端所在目录。

`max_connections` 限制同时存在的连接，断开后释放名额，重连次数没有固定总上限。空闲连接、未完成帧和发送阻塞分别受超时限制。关闭时先停止接受连接，再关闭会话，等待正在执行的数据库事务结束，最后检查点合并 WAL。

服务启动时绑定一个系统分配的回环 UDP 端口，并通过原生 `1B` 应答公布。客户端的 `15` 地址探测收到 `16` 应答后继续登录；原先的端口占位值 `1` 会让每次切换角色等待十次半秒重试。该服务只应答本地账号的固定格式探测，不改客户端重试计时或连接就绪字段。

城镇 `227` 场景就绪后，服务端依次发送 `228`、必要的 `D9` 背包同步和 `105` 装备外观刷新。时装不再排在每秒商城通知之后；重复就绪请求不会重复刷新或修改装备存档。

存档通过 `.lock` 文件的操作系统锁实现服务端实例独占；锁文件保留是正常现象，进程退出后操作系统释放锁。SQLite 启动时检查完整性并启用 WAL，不覆盖现有角色或重建存档。备份应使用 SQLite backup API，同时保留正在运行时的 WAL，不能只复制活动中的主数据库文件。

单独运行时日志在 `logs/server/`。整合入口运行时日志在对应 `analysis/client-6c6b5180/<时间>/server-logs/`；客户端启动、资源检查和崩溃诊断在同目录 `trace.jsonl`。正式服务日志记录请求类型、状态变化和错误，不记录会话密钥、明文协议内容或完整背包。

## 资源兼容与当前范围

服务端现有独立的客户端数据目录 `els_server/data/client/`，启动时校验客户端版本、数据包 SHA256 和 schema。数据包括 181,836 条道具及属性记录、4,483 条技能、9,929 条职业技能树、195 个职业模板、740 个副本定义，以及普通等级、神物、共鸣经验和掉落相关配表。业务层通过 `els_server.game_data` 读取，不在每次请求中解析客户端文件。接入范围、原生对照、重建和查询方法见 [客户端数据接入说明](docs/client-data.md)。

角色经验达到原生阈值后，等级与奖励在同一 SQLite 事务提交；重试不重复升级，编码失败会一起回滚。技能按职业、等级、封印和升级替换条件生成，角色转职时同时更新持久化技能栏。客户端已有的道具名称、分类、属性与装备计算系数用于服务端校验和属性计算。普通角色等级上限仍为 99。
