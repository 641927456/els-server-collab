# 家园布局写锁时钟修复

保存家具布局先采样时间、再等待 BEGIN IMMEDIATE。当家园契约在等待期间到期时，旧代码依然允许写入布局及 receipt。现在获得数据库写锁且复核当前角色后再取时间，直接复用原有期限判断，不改变家具、契约时长或其他经济数值。

实际隔离 SQLite 两个连接竞争同一写锁：到期边界前开始等待，在到期时放锁。父版错误保存成功，修复版明确拒绝，库逐行转储相同、没有新增布局和 receipt。第二个输入在放锁后仍未到期，正常保存一次并使用放锁后的时间。两个用例使用同一正式父版和真实契约/入场事务，临时自有库均已清理。

同型静态搜索列出其他事务提前取时的候选，但尚未逐项证明为缺陷，没有据此批量修改别的系统。公会/性能活动会话的文件没有被本批覆盖。此提交只有一个源文件，未改变客户端，未新增表，尚未安装；不代表家园访问/扩展已接通，自然 GUI 未验证。作者自审不代替精确 head 的人类审批。

运行归档回归：设置 ELS_FULL_SOURCE 为具有父版资源的完整运行树，运行 python -B test_layout_clock.py；添加 --baseline 可复现旧代码接受过期契约的结果。
