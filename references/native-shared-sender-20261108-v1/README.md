# 原生共享发送入口修复

当前 Frida 17.23.3 对同一函数仅分配两份 listener invocation data，添加监听器时却未限制数量。本服原生发送函数的主脚本、精灵恢复脚本以及后续战力、结算组件共用同一地址，实际业务监听器已经超过此容量。继续叠加发送锁会加剧回调状态损坏风险。

固定源码依据：[Frida gumdefs.h](https://github.com/frida/frida-gum/blob/1208a1266e9d28e6c958b6a167b6d944ebefaf47/gum/gumdefs.h#L452)、[添加与调用监听器](https://github.com/frida/frida-gum/blob/1208a1266e9d28e6c958b6a167b6d944ebefaf47/gum/guminterceptor.c#L1859)。本记录确认容量越界缺陷；没有把历史玩家闪退、每次重复序号或实机具体 JIC 覆盖指令认定为已完全归因。

候选把五个业务观察器及自有诊断观察器收拢到同一 JS 分发器。原生 C 锁先安装，保留一个 C 监听器和一个 JS 监听器；原有序列化、加密、递增与入队继续由原游戏执行。各组件保留独立闭包及每次调用状态，原生 InvocationContext getter 使用原生 receiver；组件异常仍进入现有错误通道。精灵恢复按原 item_test 条件装入主脚本，旧的独立 Script 不再额外注册发送监听器。

从实际已发布的 V106 父版整合，核对 2873 个父文件 SHA，保留其六个服务端业务文件及新的团本、公会旗帜战力实现。父版 PR950 的代码字节绑定于 ff83bc2f5cef207a7dd57689175c4c1589a2f21c；本批没有合并或代为批准 PR950。本批只修改三份工具文件并新增两份工具文件，不修改服务端业务、私有配置、数据库或原游戏 EXE/KOM。

相关验证：

- 八线程宿主四种场景共 704 次发送，重复序号为零且队列有序；重入发送、独立状态、原生 getter、延后注册、注销及显式异常通道通过，物理监听器始终两个。
- V106 父版自有原游戏完成认证场景并观察 32 秒，249 次进入与 249 次返回配对；七个逻辑观察器（五业务、两诊断），锁归零，无协议错误，精灵／战力／结算组件就绪。自己的进程已退出并 detach，原 EXE SHA 不变。V105 父版的旧 250/250 结果单独保留。
- 独立审查及 V106 受影响输入补审通过；曾发现并修正报告分支缩进及回调取消顺序问题。宿主中一次只读 API 的诊断夹具失败保留在私有工作目录，未变更正式 API。
