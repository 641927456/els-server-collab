## Findings and decisions

No release-blocking issue found in the frozen runtime changes. The previous launcher version mismatch is corrected by basing compilation on the actual V230 update_source and checking the compiled AutoUpdate.Version field against V231; signing metadata alone is not proof.

The guild first-login source check rejected 14 valid saved maps before checking membership. It now uses the existing TOWN_SCENES source set; the source is not a destination authorization. Existing actor identity, initialization state, membership producer receipt, live lease, scene and captured database source guards remain. For an admitted spring-origin visit, only the exact original spring or its existing SPA_PORTALS paired village is accepted on 225; the existing spring handler owns eligibility, 227 validation and durable position update. The combined tests cover all 29 legitimate sources and 19 rejection cases, three original-spring and paired-village paths, invalid/replayed 227, stale lease and changed source. Guild-ready fixtures and unrelated inventory seams mean this is not full natural guild GUI acceptance.

The performance changes cache only immutable fields from the pinned skill catalog, not ownership, learned skills, level or entitlement. The private slot-upgrade helper receives the freshly computed allowed skills from the same character snapshot; the public wrapper retains qualification. Force inventory is reused only by character_projection.force_fields on the same db/uid; other callers still read ownership. Medal UIDs are selected by owner and template and passed into the existing owner-qualified loader; the empty case does not accidentally load all inventory. Drop options previously ignored all groups except 9; selecting group 9 at SQL entry preserves that predicate. CP snapshot still starts a fresh read transaction and read_scope rolls it back before handle reuse. Coin/kill writer transaction, full receipts, replay/conflict and rollback logic remain unchanged. The author’s catalog-domain equality, fresh ownership, third-force-slot, output-wire and rollback tests bind the unchanged 11 files. Fixture speed gains are not player-visible guarantees; natural solo evidence still contains substantial queue and commit tails, with no group sample yet.

The collector adds bounded failure-only reads to existing observation scripts, without new gameplay hooks or writes. Typed fields require the known EXE identity and instruction bytes; generic module/range observations remain explicitly non-atomic. Stack candidates are marked not unwound frames. Startup wrappers preserve original returns and rethrow exceptions; source substitutions require exactly one anchor. Fault IDs and script-instance IDs bind delayed stack context. Helpers use no-window subprocesses with 3-second limits, read only process/security/wait-chain state, verify creation identity, and do not elevate, suspend or stop the game. Fault module identity refers to a disk file, not proven loaded bytes. At most two file identities and two bounded Windows event queries are collected. Paths/raw stack/token keys are excluded from new structured snapshots, existing sanitizer runs before archive/upload, and private raw logs stay off Git. Existing condition/failure locks have no reverse acquisition across the worker boundary. Related author tests cover bounded output, archive acceptance, sanitization, composition, guards and own-process Windows queries. Natural post-update faults remain required to show the missing fields in real incidents.

The 43910 native weekly quest is added to the existing periodic catalog and per-character reset/reward transaction. Current CN reference checked 2026-11-16: https://els.ztgame.com/game/m_00c-1772-003ef-179401.shtml (search returned complete official task table after direct fetch timeout), weekly per character, normal/challenge 5 stages, 3 time-space fragments and 50,000 ED. Exact original resource rows in the author manifest agree. Shared type71 progress retains maximum stage rather than adding repeated low stages, and explicit growth-guide mode constraints remain. The obsolete guide increment helper has no remaining caller and is removed. Parent actual EE returned EF2005; candidate tests cover acceptance, wrong map/mode, stage bounds, rollback, replay, cold reads, weekly reset and character isolation. Three account-weekly tasks were invisible because the QA stood in a town without NPC10025; visibility policy is not changed. No completion or reward was manufactured online.

Public signed full/chunk installs, actual loaded file hashes, two-backend delivery and mandatory 5-minute/1-minute maintenance announcements are separate delivery gates. Source PR remains unmerged without exact-head approval. Four native error groups and swallowed multiplayer damage are not declared solved by these diagnostics or offline checks.
