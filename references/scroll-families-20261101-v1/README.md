## 挑战进度与客户端支持

2026-11-01 用户明确确认：“两种挑战模式都常开”。每类每周两次等限制沿用[官方已实装说明](https://elsword.koggames.com/2024/01/january-17th-patch-notes/)，周界沿用本服现有周三10点逻辑。

现有 `reward_receipts.grant_json.challenge_clear` 已保存角色、原尝试、地图和清除时间。候选从这些真实已提交回执投影周进度，初始化时保存本类回执边界，不删除历史记录或普通袭击账本。双份战斗按原尝试内的序号去重，跨周尝试保留前半段序号；旧初始化请求重放不会再次清除新进度。没有从未知 RewardID 推造奖励或掉落池，也没有新增挑战奖励发放路径；验证的是当前已有清除记录的进度初始化。

这是必须经独立审查、由发布负责人签名交付的客户端支持候选。已在自有独立进程承载的原生代码片段中验证；没有在玩家进程或完整游戏GUI上操作或验证。

## 验证和构包

`evidence/online.json`、`evidence/local.json` 分别记录对应运行代码的15组隔离检查。各家族使用独立进程和临时库，涵盖扣物、保存、回执重放、错误阶段/失效会话、编码回滚、周限制和跨周双份战斗。实际 `Application` / `LocalSession.handle` 测试包含数量标志1的神物批量升级、贤者、遗忘、炼制和挑战入口。ONLINE模式在本机隔离应用里加载 ONLINE 运行代码，不代表公网或 FriendsSession 实测。

追加衣架回执槽同步及资格入口调整后，只复查受影响的双端用例，记录在各报告的 `follow_up_checks`。原生A22写包与A23完整解码前缀、客户端挂钩的独立进程测试见 `evidence/native.json`。没有自然战斗、自然右键全流程或正式安装结论。

```powershell
python -B validation/run_matrix.py --mode online --runtime <ONLINE父目录> --report <报告路径>
python -B validation/run_matrix.py --mode local --runtime <LOCAL父目录> --report <报告路径>
```

构包核对正式父清单及每个输入叶子的SHA，只生成差量，不安装、停服、修改玩家库或更新正式指针。三份未变化的数据副本及两端 `special_task_readers.json` 是归档验证的定位依赖，构包时跳过相同字节。新业务表仅为惰性创建的 `challenge_scroll_resets`；安装DDL为零。其他父版由发布负责人重放相同的小改动并重新核收。
