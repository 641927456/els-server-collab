# 第二批：结束请求乱序与成长地区任务续接

基于第一批相同的实际线上父版，只增加五个源码叶。与第一批七个叶无重叠，可独立选择性整合；两批合计十二个叶。

## 结果

- 原生 BB 比最后一次 AD 或结束条件通知先到时，保存当前角色、会话、原 run 对象、run ID、地图、stage、part 和 visits 对应的请求。正常击杀、条件延迟和事务提交完成后，经原 LocalSession.handle 继续处理；不在击杀事务的 shadow 中过图。
- 单人原团本、亨尼尔、疲劳、掉落及结算分派保持。dungeon_flow.py、raid_economy_flow.py 和各经济事务源码均未替换。失效租约、切角、换 run、变更游标、失败/退出后不沿用请求。
- 共享房间保留每个成员自己的请求，全部成员结束条件成熟后继续原 FriendsDungeons.end_part。只有部分成员提前发 BB 时仍等其余成员；不替队友制造请求、死亡或通关。
- 成长活动已绑定且当前符合资格的角色，续接 26690、27540～27600 八个原生地区入口。26690 仍要求真实前置 26680；后续一项项按已完成的前置接取，初始目标为零。原目标事件、领奖、奖励、地图准入均保持。
- 自动预检查和实际接取统一引用现有 ACTIVE_QUEST_LIMIT=50，修正这两处还用 30 的遗漏。没有新上限规则或概率。

## 验证

十五项隔离验证通过，无跳过：真实 Application 的单人会话、同一自有 SQLite 内两个真实 FriendsSession 的房间屏障、失效租约/旧游标/伪造信封、事务 shadow 不消费请求、击杀预提交编码失败无数据库/游标增量且保留请求、完整单人通关只付一次并冷读、八项地区任务真实目标事件和原领奖事务、重放、接取编码失败回滚、成长绑定/其他角色/活动关闭拒绝，以及 49→50 个任务的预检查和写入一致。

测试在 G 盘自有临时库中运行。房间对象由测试构造，使用真实运行源码、账户注册表、归属与成员校验、原生事件编解码及数据库；没有启动公网监听或两台自然游戏客户端。临时初始化不足、账号 ID/名称、旧 BB 同 part 的应答预期等夹具失败保留在私有工作记录，只补跑失败场景。非原生图像、自然多人战斗、自然 GUI、公网 QA 和正式安装均未据此宣称通过。

`manifest.json` 保存五叶的父 SHA 与候选 SHA；完整父清单复用相邻第一批目录。测试源码为 test_secondbatch.py；运行时把选择性融合后的独立运行根加入 sys.path，不将归档根当可运行服务。静态校验：python -B tools/verify_pr771_secondbatch.py。

## 同类遗漏核查

已证明的根因是自动接取器复制了旧 30 项常量，而普通任务现有共享入口使用 50。精确匹配 len(active)>=30 命中写入端一处；将变量名泛化后命中预检查第二处；在 els_server 下 quest/region/boost 模块展开搜索没有其他此类常量命中。两处均改为共享常量，15 项中的上限用例覆盖预检查和真实写入。这次不改变普通任务引擎或任务奖励。

50 是当前服务端已生效的兼容上限，不是本轮重新确认的最新官方上限。2026-11-03 核读[国服官方任务介绍](https://els.ztgame.com/game/003-1650-0034f-783998.shtml?mt=847)，并对照 2026-10-30 已保存的 CN-039 正文，最新说明是外传任务最多 20 个，其他任务无接取数量限制。现有通用 50 项限制与此仍有差异；需结合已装客户端的任务容器/同步容量和类型映射继续修，不能用本批统一常量宣称最新任务上限已还原。
