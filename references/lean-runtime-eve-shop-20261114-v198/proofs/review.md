# V198 定向审查与核收

本批以已安装 V197、Git head 5ff2b668f94307560f7f0563d5a1a917e6cf3243 为父版。按 differential-review 方法检查实际消费入口、签名/目录/安装边界和经济事务；这份发布整合审查不代替独立审查或精确 head 的 Git 合并审批。

整合保留 V197 四十处业务修复和现有线上 GM 差异。签名运行文件十三处变更：一处商城业务、十二处技术支持。云端运行只消费商城与宠物附件共享表路径两处；云端未消费的旧客户端工具不批量覆盖。发布源码归档同时保存十三份通用叶子与十四份启动器源码/生成绑定，避免将云端两文件误写成全部交付范围。

商城公共过滤入口通过 careers.RULES.unit_type 选择职业商品的原始角色类型，其他商品仍沿用原生记录。两条伊芙转职券保持 50ED，商品类目、消费/幂等事务和服务端资格复用原流程。最终精简 3.14t 实际导入路径下，十五角色×541目录、两条购买转职链、冷读、重放、资格拒绝及预编码故障回滚通过；最终 TLS 测试也通过。原客户端商品显示/点击未自然验收。

启动器十一份 C# 与 manifest 的差异已读：只有四份美术与两份生产签名清单嵌入。联网108文件，服务增量1980文件，重叠10文件逐SHA相同，唯一2078文件。排除旧父928条路径并新增两份 native_support；裁剪不等于云端删除。客户端 Blowfish 与服务端 DES 仍为原字节和独立 ABI；测试最初错误插入客户端 vendor 造成导入失败，现已改为实际安装的服务端 3.14t，不为测试恢复被裁依赖。

签名解析、每叶SHA、服务增量绑定客户端 raw identity、来源版本和共享叶一致性均继续检查。CurrentModule 把复用快速入口绑定当前 ZIP/清单身份；另一个 AvailableModule 只判断服务端内容是否已下载，真正准备仍经 EnsureLocalModules/PrepareCore 的当前身份和全叶验证，不用该提示入口选择运行目录。目录拒绝链接；下载成功只清理自身命名的顶层包/分块/part，原运行目录、存档、私有配置和无关备份保留。设置与凭据继续按原私有 profile；下载、会话和新日志跟随所选客户端 .els-runtime。按钮只在本地选中后显示且需明确点击，首次本地不需要 Git。系统长路径策略不改。

native_support 的四份准备脚本、七份 JS 及 Frida 原生输入逐SHA相同，复用作者相同输入的原生准备/进城/PvP源就绪结果；本批没有新 Hook，也未启动或控制玩家游戏进程。最终108文件的真实原生预检通过，原EXE/KOM哈希保留。

生产签名实际EXE的离线初装/重复、3.14t安装器、旧同内容目录迁移/零下载复用、真实GameServer TLS、控制器两分支代码恢复均通过。公开初装、V197升级、按需增量、缓存清理及正式双端加载结果分别由发布目录的阶段回执绑定，未完成的阶段不在此提前写成通过。恢复回到精确V197代码/支持叶，不恢复玩家或账号库，保留V197钓鱼兼容读写规则。

历史检查以精确父版归档及冻结SHA为依据，不对共享开发目录的当前未归档状态做笼统历史推断。原客户端各玩法自然GUI/战斗与线上残留秒级慢请求仍是独立未完项；V197采样报告不支持“所有卡顿已解决”的结论。

公开服务增量测试触发反射宿主的旧 .NET 路径缓存：宿主先用 Path 加载程序集，随后才调用启动器设置路径开关，造成长路径异常。正式生产 EXE 以自身入口实际执行公开签名元数据读取并写入超过300字符路径成功；生产字节无需变更。两个自有反射宿主现于首次 Path 使用前设置同样开关，仅补验受影响模块部分，已过的公开客户端初装回执继续复用。production-long-path-proof.json 保留实际 EXE 证据。
