# 交互式登录与频道重连修复

正常启动仍运行隔离探测用的定时选角与选频道代码。重连认证尚未完成时，这些调用可提前发出 `0x490`；服务端按阶段校验断开连接，客户端停留在连接服务器或选角界面。

修复在原有角色帧回调中限制测试入口：`lightweightPlay` 的交互式启动沿客户端原生按钮和回调继续，隔离探测保留原有自动进入能力。不放宽服务端认证或阶段校验，不新增 Hook，不改原游戏 EXE/KOM 或存档。LOCAL 的艾因等既有分支保留。

`source/` 保存两种已交付 trace 及组合器的精确字节、对应摘要合同；`source/parents/` 是可复现旧行为的静态源文件。组合器和资源合同同时更新，未固定的 trace 继续拒绝。`launcher/` 保存 V53 变更的启动器源码及新签名资源；未改的构建资源沿已核 V52 父版复用，继承资源没有随本目录重新分发。父版摘要和适用范围见 `source-contract.json`。

V53 的 LOCAL 首次安装、V51 升级和重复运行沿实际 C# 入口验证，保留九级精确前驱链及摘要拒绝检查。签名组件与本地实际运行快照分别核收，结果见 `installation-evidence.json`。本目录是可审查来源与交付记录，不直接切换 main 的历史运行清单；Git 首次安装继续沿统一启动器与已签名组件。

验证命令：

```powershell
python -B -m unittest tests.test_login_reconnect_support
```

此测试执行实际 JS 角色帧回调：旧交互式重连可重放两个额外调用，修复后的交互式流程为零，隔离探测仍保留两个调用。它不启动或附加游戏。自然玩家重开后的进城结果与这些离线、升级和安装检查分开登记。
