# CALLM 来源与赫尼尔活动生成链补齐

旧增量重建过程只将普通 CALL 交给快速常量追踪；CALLM 未报告为未解析调用，也未交给共享 CFG 分析器，导致合法实体仍缺少准入。现统一对所有原生生成调用使用既有 Flow；该共享分析器和正式开发编译器已经支持 CALLM，本次不再走旧快速追踪。遍历 4147 个 NPC 来源身份后，补齐 35460、35540、35870 三模式九处阶段目标：9754、9863、9868、12585。12585 的原 Lua、枚举和原生字符串均存在，新增一条初始化／正式 HP 身份；四条精确模式 HP 绑定沿用既有已批策略，已有行保持。

五个运行数据文件及两个未变开发工具逐 SHA 保存在 source，基于实际 native-hot-time-permanent-20261104-v1，保留此前机关、掉落、玻璃门和热时增量。当前父版九例实际拒绝，候选九例实际 DungeonRun 和双人 Application/TLS 生成均通过；重复 ACK、客机拒绝、混合坏批次原子性及余额保持均通过。12585 两例原生用户创建者上下文、外部创建者拒绝及三类掉落目录（53／33／22 图）通过。

35870 第20／21阶段的来源现已闭合。12582 虽有注册和准备项，但没有活动生成者；此前未定义枚举所在的 B 回调被前置 RATE=100 转移支配。原客户端按数字事件索引递增读取，成功状态变更后退出本轮事件循环；原生构造、RATE 分派和16组计数器正反例验证这些指令分支后，以真实初始实体重建完整活动闭包，未知状态／生成参数为零。不增加替代 NPC，不声称恢复原档不存在的 Lua 文件，不修改原 EXE/KOM。

native-event-priority-tests 只验证原生指令块，双人测试使用显式后期房间夹具；它们不代表自然全程战斗／通关已验。首次原生夹具漏置 R12 事件行失败保留，补齐该输入后原断言通过。repair 脚本在原私有分析布局执行；不附原始资源、数据库、抓包或运行日志。本目录为候选来源归档，安装状态另记。
