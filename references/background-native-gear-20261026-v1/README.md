# 后台原生装备验收源码归档

对应 Issue #535。`sources/` 的10份源码保持合格运行的原字节，原工作区路径、大小与 SHA256 见 `manifest.json`；不是可直接在协作副本执行的独立安装包。

模型解密和解压成功后，私有桌面的 Direct3D9 设备创建返回 `0x8876086c`，空设备再导致原 D3DXCreateMeshFVF 失败，最终被统一显示为“脚本损坏”。合格入口在正常渲染桌面创建自己的屏幕外 NOACTIVATE 窗口，运行前按函数实际地址去重输入／焦点／光标拒绝挂钩，并通过完整自检才恢复新进程主线程。辅助程序保留原始创建结果和句柄，GUI 放在从未切换的私有桌面。原模型解析、SDK和图形成功返回不被伪造。

`qualification.json` 是脱敏核收：四普通初鉴、四影子初鉴、四穿四卸及第二独立客户端进程重登通过。普通初鉴0ED、不耗卷；原影子初鉴每件扣1卷。UID、+11、炼制21和原词条保持；两次窗口均实际核对屏幕外、不可激活、非前台，自有认证、私有服务和进程收尾。调用原生回调，不宣称自然键鼠点击、逐像素界面或战斗验收。历史探针输出中名为 `enhancement` 的旧偏移值不作强化证据；强化／炼制使用真实存档同UID完整字段比较。

复验由维护者在完整受控工作区进行：按 `source_workspace_path` 及 SHA 核对源码，保留对应私有运行资源、锁定客户端、既有只读指令参考和测试TLS环境，再使用原 `后台验证入口.py`。这些资源、证书、账号凭据、原始日志及数据库均不入Git。入口发现已有游戏或共享发布锁即拒绝新启动；仅分配新自有QA，不能指向玩家账号或生产数据库。CI只校验归档完整性、隐私和源码，不启动客户端。

装备业务修复已由 PR512/513 合并并双端安装。`dual-installation.json` 重新核实较新的双端正式包完整保留这10叶修复及其消费者，线上实际1206个文件、单机1682个运行文件核对通过。此归档不再安装旧包、不覆盖后续增量、不切换正式指针、不重启服务，也不把屏幕外测试策略接入正常玩家启动入口。

恢复方式：结束本次新建进程及其Job，关闭自有桌面、桥接和私有服务，精确清理自有QA认证；不恢复玩家／账号库。此前失败记录继续保存在受控工作区，本次合格件未覆盖历史失败。
