# 原生发送串行化候选

阻点：固定客户端映像中，3B7D860 在加密前通过 1271E60 读 SAS+0x50，生成 MAC 后才通过 3B817B0 递增。682D80 是异常表函数范围内唯一直接调用该加密函数的入口；其统计锁在加密之后，687580 的队列锁也在加密之后。并发调用可能产生相同认证序号，或让较新序号先入队。

服务端跳过序号校验无法可靠区分重放和两个不同业务请求，单独把递增改成 atomic 也不能保证加密与入队顺序。最小候选在完整 682D80 调用期间持有进程内递归锁，继续执行全部原生序列化、加密、MAC、递增和队列；不读写报文、SAS、资格或经济数据。

目标原 EXE SHA256：6c6b51809aec90f9b717a9e55d679f221315a6296d69da80510e3456423a1709；参考映像 SHA256：c8815e00b737c6890f87929a48cac7a6905d237fe4f04f4e8cf53aec3bfd6229。沿既有支持组件生成器核全部映像和未被现有观察器占用的函数体锚点，原 EXE/KOM 文件不改。

锁属于当前进程的当前脚本实例，不保留任何游戏对象或连接地址，无跨角色/入图代次状态。重复安装返回同一控制器；CModule 原生回调等待锁，不持有 JavaScript 全局锁。只在游戏进程退出后卸载脚本，不提供运行中销毁锁入口，避免活动 onLeave 或等待线程引用被释放。退出恢复原函数，不持久化游戏数据。

验证：原生只读计数指令离线交错回放；自有独立宿主进程中使用相同原生计数指令、多线程发送/排队、嵌套调用及已有 JS 观察器共存。静态合同与宿主压力不等于自然游戏实测。新 Hook 未独立审查、未在自有游戏进程核加载前，不签名发布、不接入正式启动器。当前线上维护窗口保持不动。
