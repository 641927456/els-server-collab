# 地雷退场修复与原生发送序号候选

地图30252中的Altera_Mine.lua爆炸结束沿原生DYING_END发送AD，但已有有限来源表未登记class102地雷，导致缺AE/AF。新增13个精确资源来源，复用既有无奖励退场入口；原957条规则字节保留，不新增运行分支、经济写入或数据库表。服务端可交付范围只有source-manifest.json的server_delivery_files，不将experimental_support_files并入安装清单。

13个来源均通过实际Application及认证TLS；首次AE/空AF、精确重复仅AE、经济保持和十种来源篡改拒绝通过。两人共享路径验证了队长/参与者资格、广播、迟到小节退场和重复请求。场景通过正常副本入场后使用显式自有夹具，不能当作自然通关或游戏闪退已消除。

原生序号调查在固定原映像中发现3B7D860先读SAS+0x50，生成认证密文后再递增，完整682D80入口未覆盖此过程的锁。异常表范围内唯一直接加密调用点为68318C。原生指令的受控交错可产生1039/1039，并在未修改服务端认证/序号保护的输入器中复现拒绝；串行输入1039/1040通过。原生接收谓词的旧回放不能单独证明实际接收调用策略：当前6817E0调用3B7E290时第二参数为0，完整调用链以本批调查为准。

`repair-v6/candidate/tools/native_send_serialization.*`是未接入启动器的实验候选：CModule回调使用进程内递归锁覆盖完整原生编码/加密/入队，继续全部原函数，不改EXE/KOM文件或服务端反重放策略。独立自有宿主8线程648次发送，基线有78次重复；候选无重复/乱序，嵌套发送、JS观察器共存和重复安装通过。这是宿主调度压力验证，不能代替自有游戏加载及独立Hook审查。其生命周期、原生阻点及恢复说明见repair-v6/native-send-support-plan.md；完成这些前禁止签名发布。

旧背包游标拒绝没有新错误游标样本。已有原生13E4030/1382280/138ECC0及12份历史请求证明完整2A库存后5BF初始游标为{0,0}，既有隔离TLS成功结果复用；缺少正确报文的历史异常不通过放宽初始化资格处理。33242旧2CE/AD拒绝同样缺原报文及新复现，继续列未确认，不登记为修好。线上重复序号的具体一次报文也不足以判定是两个不同请求还是同一认证报文重复；原生竞态是已证明的可行触发路径，尚未自然复现那次玩家断线。
