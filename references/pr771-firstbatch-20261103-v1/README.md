## 结构与来源

`manifest.json` 绑定 7 个候选文件及其实际父文件 SHA；`parent/` 保存这 6 个既有叶的原字节，`online/` 保存候选；第 7 叶是新宠物券来源数据。完整父清单的 SHA 为 `f9a78ccad1b82e504a0402dace4c186908afac64fbb086c2ebddcff6f5bcf2f1`。

宠物券数据取自 PR #771 精确 head `6e844dfda2b1600c7735ba0a9965cd28b4e1f21e`。其模板记录仅标识/文本块与基础券不同，共用原始 DTO 读者；这是源记录/静态资格，不冒称新增原生执行回执。消耗品原生六字向量、等级和冷却已由同一锁定客户端记录核对；没有猜测概率或奖励。

## 验证与边界

15 项隔离业务验证通过，覆盖十物品扣物/冷读、原生冷却、同绑定实例选择、编码失败无增量、六券权益/前置、并发重放、原 15 日限时权益到期与永久转换、MP 比例绑定、失败回当前绑定/设置、非法信封和过期租约拒绝，以及手动/宠物共享冷却。

首轮三个夹具问题保留在私有任务记录：同绑定模板按原选择规则先消费旧栈；懒表尚未初始化就由夹具 DELETE；原限时券属于禁止通用新产出且为单实例，须在自有临时库构造合法历史持有行。只修正夹具，复用 11 项未变成功结果，重跑三个受影响用例；生产资格未放宽。

交付复核另补一项真实拒绝路径：存档账号归属不符时，不能在失败回包中读回该角色设置。只读恢复事务复用 require_active_character/require_owner，并在读取后复查所捕获会话；此新增用例及三个相关反馈用例通过，其他十一项未变结果复用。

`test_firstbatch.py` 只用于独立测试目录和自有临时库，不是生产启动入口。测试时把已按本清单融合的隔离运行根放在 sys.path 前端，再执行该模块。静态归档检查：`python -B tools/verify_pr771_firstbatch.py`。本提交不自带私有静态客户端库、运行凭据或玩家库。

自然 GUI、原生药效表现、公网自有 QA、正式安装和本地单机/签名载荷交付尚未完成。发布须由指定负责人核届时真实父版，选择性合入这 7 个叶，保留其他新增修复；不能把旧根运行树或本 PR #771 整包覆盖线上。若父版漂移，只使实际受影响验证失效。
