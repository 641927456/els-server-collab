# 差异审查

四个服务端叶，按涉及经济事务的高风险改动审查。复用 PR #912 的源码历史和最新 Quest 运行父，仅增加批次边界和纯场景准备前移。全树直接 write_transaction 调用 63 处；新 batch_should_yield 只在 coin/death 的批处理循环使用，其他事务不改调度。两处 _commit_ready 调用属于死亡、时钟各自线程，未引入跨线程 SQL 句柄共享。

检查结果：未发现新的权限绕过、经济增量或回执缺口。每个已执行请求保持原 SAVEPOINT，实际 FULL 提交之后才完成 Future；物理提交失败不报告成功。让出的未执行后缀在本线程保留，先于后到请求与退出哨兵执行；生产者的角色域直到其 Future 退休才释放。读者和私有路径继续逐批重核，未缓存账号资格或玩家数据。

首版逐条取队列的实验改变了整批 ROLLBACK 时尚未取出请求的范围，相关拾取回归失败。已保留失败并修正为预取有界批次、仅成功提交后保留未执行后缀，原完整 SQL／错误语义回归通过。一次测试缺失 sibling import、一次测试变量遮蔽 closing、两次负载启动器配置错误均发生在夹具，修正后分别重跑受影响部分；没有通过放宽业务断言解决。

边界：4ms 不能打断长单笔事务或操作系统／磁盘等待；竞争加重时提交次数可能增加，需要在同规格主机继续衡量提交成本和尾延迟。没有把本地四核、loopback 或顺序单元当作 5M 公网证明。本审查由本会话执行，不充当 Git 精确 head 人类审批。
