# 同路径重复解析检查

根因是私有写者在每次提交时，对相同原始Path做两次内核路径解析。正常传入路径与绑定路径相等时，比较不会提供新的绑定信息；每批写入前原有的实际路径、文件ID和连接检查仍负责新鲜性。此处是性能问题，没有把它认定为权限绕过。

| 搜索 | 结果 | 处理 |
|---|---:|---|
| PositionWriter.defer内的精确AST比较 | 1 | 已复现 |
| 同类PositionWriter比较 | 3 | 全部确认 |
| 同形私有写者比较，扫描已部署共同服务端全部Python源码 | 5 | 坐标3、死亡1、时钟1 |
| 扩展到两个resolve的任意相等/不等比较 | 35 | 其余不纳入本次修复 |

五处均为P2性能问题，确认程度高。修复先比较原始Path，只有不同路径才解析并比较；同路径正常请求不解析，等价别名继续解析两次，错库继续拒绝。DeathWriter._connection、PositionWriter._run和ClockWriter._connection的每批实际文件检查保持原样；事务、保存点、FULL、提交后完成和推进顺序保持原样。

扩展候选中的SQL实际连接校验、不同参与者存档比较和经济事务来源校验，不具备这里“唯一私有写者＋每批独立检查实际文件”的完整证据，保留原行为。噪声已超过一半，搜索到此停止，未泛化修改这些权限边界。

实际SQLite测试验证了正常路径、等价别名、错库、死亡/时钟保存点回滚、完成后冷读以及落库屏障。CI采用三个指定写者的AST归一化比较作为回归规则：仅允许提交守卫的相等路径短路，其余原方法和连接/事务实现必须与父版一致。完整命中列表仅留本地analysis。
