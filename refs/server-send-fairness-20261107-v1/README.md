# 城镇发送与副本读取优化

城镇成员列表、后台维护和副本状态重复读取会推迟坐标广播及过门处理。本批候选修改共同服务端的22个模块，基于 `native-achievement-equipment-consumption-20261107-v1`，完整保留父版新增的成就历史和条件类型。拾取、死亡和过门仍走原隔离业务队列。候选尚未安装，源码合入和安装分别登记。

每条连接保留一个有界发送者。只有不携带自身属性来源回执的 `0x22a/0x22e` 城镇批次允许入队后返回；同一成员通知区间、同一场景内，尚未编码的同角色坐标可由更新值替换。场景变化、经济回复及属性来源回执保留实际写出后的确认。队列限制8组／2MiB，城镇组256条／256KiB，合并不延长首次发送期限。

共享配额按实际原生帧字节计费，仍用两条FIFO通道和4KiB字节轮转；只有纯坐标进入坐标通道，成员列表保留普通通道。当前实测预算4.4Mbps，默认0沿用原部署行为。5M策略另做公网校准，协议帧预算不包含TCP/TLS头。安装只合并该配置项，线上原有192连接配置、存档、账号、证书及私有路径不能被公开模板覆盖。

普通城镇通知和发送中新到达的通知立即唤醒原轮询。坐标在生产者释放世界锁后，按监听事件循环合并一次跨线程唤醒。后台维护和普通移动在捕获旧邮箱之前允许同连接发送其他角色的坐标；一旦捕获成员创建，先关闭这个窗口，保留创建先于后续坐标的原屏障。城镇维护每片最多约2ms后交还连接，未完成步骤沿原生成器继续，不能跳过维护。真实TLS验证了维护／移动捕获前后四种顺序、邀请屏障及原生帧序号。Windows接入套接字明确设置TCP_NODELAY。

发送BD后直接绑定本次场景的时钟上下文，避免锁定滞后的实时快照。完成BB小节时按已完成状态判断时钟，不再按下一道门反查。严格原生9E维护包仍经过原处理、序列、租约和奖励报告检查；只有纯维护回复省去重复活动观察，真实状态或等级变化继续刷新。45次死亡／拾取、3个房间、3个9E确认和6次场景时钟检查已有实测。

无共享房间的副本请求不再读取一个只供共享路由使用的身份，随后继续执行原单人处理器的身份和资格检查。实时视图每次发布仍重新读取账号启用状态；只有完整指纹、全部启用标志及普通单人／城镇条件相等时复用不可变图。共享副本、婚礼、拍照、PVP等保留原生产者；失败清空快照。发布使用现有线程专属只读SQL连接，不缓存授权结果。新账号的中继入场先刷新独立授权读取，消除认证成功但下一次100ms轮询尚未包含账号的竞态；真实组队、断线、UDP房间权限和新账号入场四项检查通过。

成就无变化时，先在真实只读事务中执行原进度规划及前后守卫，省去争抢唯一写者。发现变化后在原写事务内重新规划、编码、记录和提交，不能把只读结果直接用于写入。持有其他写者时的无变化读取、真实完成、重放、编码失败回滚和读写间历史变化六项SQL检查通过。29种父版条件及其来源映射原样保留。开服预热成就不可变目录／奖励表及已观察到的延迟导入，并预备实际账号查询语句；不提前读取或修改玩家进度。

两段28字节属性与完整原生角色序列化共用纯构造函数，保持LuCiel原规则。真实SQL中普通角色查询77→2次、LuCiel77→37次，150个生成输入及2个边界的完整封包逐字节相同。城镇外观只读取穿戴装备：149件物品的角色读取149→10件，穿戴变动后9件；完整背包仍149件，缓存键分离。五处写者提交守卫只对原始Path相等省去重复解析，实际文件身份、别名检查、FULL、保存点、回滚与提交后ACK不变。

低价值诊断日志在原后台线程等候10ms后批量输出，游戏线程不等待。同样200条日志输出200→69次，FIFO、关键错误首条、溢出及关闭保持；关键错误排在诊断之后可能等待该窗口。
