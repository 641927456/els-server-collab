# 城镇发送与副本读取优化

城镇成员通知会阻挡已就绪的坐标，共享带宽配额又会让较大的成员列表排在小坐标之前。本批调整共同服务端的17个模块，基于 `native-achievement-foundation-20261107-v1`，保留父版成就、活动预览、任务、组队、GM锁序和退出清理行为。拾取、死亡和过门继续使用原隔离业务队列。

每条连接保留一个有界发送者。只有不携带自身属性来源回执的 `0x22a/0x22e` 城镇批次允许入队后返回；同一成员通知区间、同一场景内，尚未编码的同角色坐标可被更新值替换。普通通知、场景变化和经济回复保留顺序，业务等待真实写出；属性来源回执也继续在写出后确认。

共享配额按实际原生帧字节计费，两条发送通道按4KB字节额度轮转。只有纯坐标进入短消息通道，成员列表使用普通通道；每个连接的帧序号和先后顺序保留。连接队列限制为8组／2MB，城镇组为256条／256KB；从首次入队开始计算完整发送期限，合并不延长期限，超时关闭连接并清理等待者。默认 `egress_mbps=0` 保持旧配置行为，5M测试使用4.4。该值不包含TLS/TCP头部，公网验收另做5M策略校准、网卡与自有TCP计数核对。

普通城镇通知立即唤醒原业务轮询；通知在上一批发送中到达时，发送结束后也立即续接，保留通知、邀请和坐标的原顺序。前台连接保持原轮询间隔。坐标在生产者释放世界锁后唤醒对应连接，第一条坐标进入已有普通通知的邮箱时也会唤醒。空闲连接等待事件或下一秒时钟，存在待发坐标时使用1ms重试。接入连接明确启用 `TCP_NODELAY`：实际Windows接收套接字的protocol=0，绕过了运行时默认启用条件。普通业务通知仍保留原有屏障。

满级且状态未改变的动作复用原时钟判据，原精确指纹未变的B8可以复用实时快照；跨阶段、最终结算及状态变化仍刷新。发送BD后直接记录本次已发送场景的计时上下文，不从可能滞后的实时快照锁定场景。两段28字节属性与完整原生角色序列化器共用同一纯构造函数，保留LuCiel原有绝对HP规则。真实SQL对比中，普通角色查询由77次降到2次，LuCiel由77次降到37次，一级、满级及错误账号拒绝均通过。

城镇外观改为只读穿戴装备，完整背包默认入口保持原样；两种投影使用独立缓存键。真实149件物品的角色由读取149件降为10件，穿戴变更后为9件；完整背包仍为149件，外观封包逐字节一致，返回值修改不会污染下一次读取，提交后的装备变更能刷新。

150个生成输入和2个边界输入的完整原生角色封包及两段属性逐字节一致，包含父版新成就状态。当前源码在正式服同样的1ms计时下通过成员通知先于坐标、邀请屏障、45次死亡／拾取、3个房间与6次换图／过门时钟检查，奖励冷读与ACK一致。CI运行27个帧长、状态、顺序、通道分类、字节轮转、取消、超时及工作线程控制测试：`python -B refs/server-send-fairness-20261107-v1/verify_contract.py`。

失败结果保留于 `negative-*.json`。v2～v5隔离入口未复用正式服已有的 `__main__._native_timing`；v4另有一名前台连接不足整300秒，健康断言保持失败，之后每个角色从正常入城完成起测试完整5分钟。v6入口计时已一致，仍未通过公网门限。测试监控已移除在TCP事件循环上每秒构造／写出完整进度快照的开销，保留请求直方图、轻量资源／TCP观测和冷库核对。17模块v8的公网5分钟中，副本与城镇处理门限通过，城镇送达P95/P99为51/90ms，未通过40/80ms门限。后续修复发送中新通知被重新推迟50ms的调度路径，正在继续验收，未安装本批优化。

本地50人、16城镇＋34副本的完整5分钟测试中，副本处理指标通过，城镇送达与连续性未通过。新通道分类的50人60秒诊断也未通过城镇门限，不能宣称50人达标。人数、组成、持续时间和全部门限以实测回执为准；5M无法承载50名角色全部同城持续移动的原始广播量。

坐标、死亡和时钟写者的五处提交守卫先比较原始Path；同路径省去两次解析，别名继续解析，错库继续拒绝。每批实际文件检查、事务与保存点完全保留，相关冷读与回滚测试通过。

源文件、父版及测试均有SHA绑定。数据库结构、FULL耐久级别、提交后回复、客户端协议和原游戏EXE/KOM保持原样；两端交付同一签名组件，分别保留IP、账号、存档、证书和私有路径。原始日志、凭据、证书和玩家数据库不入Git。协议负载不是自然GUI、实战或UDP协作流量的验收，B3换场景处理门限也不代表整个客户端资源载入时间。
