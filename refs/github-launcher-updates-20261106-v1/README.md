## 下载和核验

- `latest.json` 走 GitHub 最新稳定发布地址；EXE 使用版本与 SHA 前缀确定的不可变发布标签，避免频道更新后下载串版。
- 完整包和 59 个分块按运行包 SHA 固定标签。首次准备或大量缺失仍走原完整包；少量缺失下载签名索引中的相关分块。
- GitHub 使用 Windows 默认 TLS 证书链和主机名验证，最多五跳重定向，只允许指定仓库和 GitHub 官方资源域。每次下载仍核对发布者 RSA 签名、精确大小及 SHA256。
- 保留原子安装、旧环境、反降级和失败激活保护，不覆盖账号、存档或私有配置。

## 发布顺序与边界

当前 GitHub 启动器发布标记为候选预发布，未切换旧服务的 `latest.json`，正式版本仍是 V82。须完成本 PR 精确 head 审批及 CI 后，按既有发布锁核父版，再将同一候选提升为稳定版。原入口一次性交付 V83，实际旧 V82 下载后核选中组件，再观察更新渠道至少 120 秒并登记当前指针。

仅更新启动器分发，不停游戏服，不替换游戏代码，不恢复数据库。双端已有相同运行内容时登记已包含。旧版地址写死且不跟随重定向，旧入口需要保留到迁移完成；旧版仍可能从旧入口下载这一次过渡 EXE。不能据此声称全部存量玩家已迁移，或 22/24/50 人游戏容量已经达标。

公网记录证明本次测试网络可达，不能承诺所有地区的 GitHub 下载速度。迁移完成后仍需按既有五分钟标准复核有玩家时的实际业务表现；本次不重复未变化的服务端容量测试。
